ArkType converts in both directions, and once a schema is a Type, it compares with any other.

| direction                             | API                                             |
| ------------------------------------- | ----------------------------------------------- |
| Type → JSON Schema                    | `T.toJsonSchema()`, `T["~standard"].jsonSchema` |
| JSON Schema or Standard Schema → Type | `fromJsonSchema(schema)`                        |
| compare any of them                   | `.extends()`, `.equals()`, `.overlaps()`        |

## Type to JSON Schema

Every Type has a `toJsonSchema()` method. Nothing else to install:

```ts
const User = type({
	name: "string",
	"age?": "number.integer >= 0"
})

const schema = User.toJsonSchema()
```

```json
{
	"$schema": "https://json-schema.org/draft/2020-12/schema",
	"type": "object",
	"properties": {
		"name": { "type": "string" },
		"age": { "type": "integer", "minimum": 0 }
	},
	"required": ["name"]
}
```

Some things a Type can check, like a `Date`, a `bigint` or a custom `narrow`, have no JSON Schema equivalent. `toJsonSchema()` throws on those unless you tell it what to write instead. See [To JSON Schema](/docs/json-schema/to-json-schema).

Libraries that accept any [Standard JSON Schema](https://standardschema.dev/json-schema) read it from `T["~standard"].jsonSchema`, which never throws for those parts. See [Standard JSON Schema](/docs/json-schema/to-json-schema#standard-json-schema).

## JSON Schema to Type

`fromJsonSchema` reads a JSON Schema into a Type:

```ts
import { fromJsonSchema } from "arktype"

const User = fromJsonSchema({
	type: "object",
	properties: {
		name: { type: "string" },
		age: { type: "integer", minimum: 0 }
	},
	required: ["name"]
})

User.expression // "{ name: string, age?: number % 1 >= 0 } & isNonArray"
// ArkErrors: age must be an integer
User({ name: "Ada", age: 1.5 })
```

A schema written in the call infers its type, so `User` is a `Type<{ name: string; age?: number }>`. It reads a [Standard JSON Schema](https://standardschema.dev/json-schema), like a Zod schema, too. See [From JSON Schema](/docs/json-schema/from-json-schema), and [Keyword support](/docs/json-schema/support) for which keywords it understands.

## Compare schemas

Read into Types, JSON Schemas, Zod schemas and your own Types compare with each other, so you can check in CI that a new version of an API schema still accepts everything the old one did:

```ts
import { fromJsonSchema } from "arktype"
import { z } from "zod"

const V1 = fromJsonSchema(z.object({ id: z.string(), age: z.number() }))
const V2 = fromJsonSchema({
	type: "object",
	properties: { id: { type: "string" }, age: { type: "number" } },
	required: ["id"]
})

V1.extends(V2) // true: V2 accepts everything V1 did
V2.extends(V1) // false: V2 accepts { id: "a" }
```

[Compare schemas](/docs/json-schema/compare) covers every comparison and what `true` proves.
