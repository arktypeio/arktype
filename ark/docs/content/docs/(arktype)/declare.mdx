---
title: Declare
description: Define a Type checked against an existing TypeScript type, exactly or as assignable to it.
---

If your ArkType definitions are your source of truth, infer your TypeScript types from them: `type User = typeof User.infer`.

If the TypeScript type comes first, `type.declare` checks that a definition matches it. Object keys are autocompleted, and a definition that is too wide _or_ too narrow is a type error:

```ts
// @errors: 2322
type Expected = { a: string; b?: number }

const T = type.declare<Expected>().type({
	a: "string",
	"b?": "number"
})

const Bad = type.declare<Expected>().type({
	a: "string",
	// narrower than number
	"b?": "1"
})
```

Optionality can also be expressed in the value instead of the key:

```ts
type Expected = { a: string; b?: number }

const T = type.declare<Expected>().type({
	a: "string",
	// same as "b?": "number"
	b: "number?"
})
```

`declare` works with any definition, not only objects:

```ts
const Name = type.declare<string>().type("string")

const Entry = type.declare<[string, number]>().type(["string", "number"])
```

To reference your own aliases, use the `declare` method of your [scope](/docs/scopes), like `$.declare<User>().type(...)`.

## `side`

A Type with morphs or defaults has different input and output types. For example, `string.numeric.parse` accepts a `string` and returns a `number`.

By default, `declare` compares your definition to the declared type as a whole, so a morph only matches if the declared type includes it. To compare only the input or output, pass `{ side: "in" }` or `{ side: "out" }`:

```ts
// @errors: 2322
type Expected = { a: number; b?: number }

const Bad = type.declare<Expected>().type({
	a: "string.numeric.parse",
	"b?": "number"
})

// the output must match Expected
const T = type.declare<Expected, { side: "out" }>().type({
	a: "string.numeric.parse",
	"b?": "number"
})
```

## `assignable`

A form often accepts less than the API type it submits: a key the API leaves optional or nullable is required, or a string is limited to a few values. To check only that what your definition infers is assignable to the declared type, pass `{ assignable: true }`. The Type keeps the type its definition infers:

```ts
// @errors: 2322
type Contact = { name: string; email?: string | null; kind: string }

// email is required, and kind is narrower than string
const ContactForm = type.declare<Contact, { assignable: true }>().type({
	name: "string",
	email: "string.email",
	kind: "'person' | 'company'"
})

type ContactForm = typeof ContactForm.infer
//   ^?

const Bad = type.declare<Contact, { assignable: true }>().type({
	// wider than string
	name: "string | number",
	kind: "string"
})
```

A key declared optional may be left out, or written optional or required. A required key must be written required, and a key the declared type doesn't have is still an error.

## Index signatures

A key that isn't one of the declared type's own keys is checked against its index signature, if it has one. That matters with `Omit`, which leaves only the index signature of a type like `{ name: string } & Record<string, unknown>`: each key it dropped is declared `unknown`, so `"string"` there is an error rather than a Type that infers `unknown`. Declare the keys you want, or use `{ assignable: true }` to check them against `unknown` and keep what they infer.
