---
title: Declare
description: Define a Type that must match an existing TypeScript type exactly.
---

If your ArkType definitions are your source of truth, infer your TypeScript types from them: `type User = typeof User.infer`.

If the TypeScript type comes first, `type.declare` checks that a definition matches it. Object keys are autocompleted, and a definition that is too wide _or_ too narrow is a type error:

```ts
// @errors: 2322
type Expected = { a: string; b?: number }

const T = type.declare<Expected>().type({
	a: "string",
	"b?": "number"
})

const Bad = type.declare<Expected>().type({
	a: "string",
	// narrower than number
	"b?": "1"
})
```

Optionality can also be expressed in the value instead of the key:

```ts
type Expected = { a: string; b?: number }

const T = type.declare<Expected>().type({
	a: "string",
	// same as "b?": "number"
	b: "number?"
})
```

`declare` works with any definition, not only objects:

```ts
const Name = type.declare<string>().type("string")

const Entry = type.declare<[string, number]>().type(["string", "number"])
```

To reference your own aliases, use the `declare` method of your [scope](/docs/scopes), like `$.declare<User>().type(...)`.

## `side`

A Type with morphs or defaults has different input and output types. For example, `string.numeric.parse` accepts a `string` and returns a `number`.

By default, `declare` compares your definition to the declared type as a whole, so a morph only matches if the declared type includes it. To compare only the input or output, pass `{ side: "in" }` or `{ side: "out" }`:

```ts
// @errors: 2322
type Expected = { a: number; b?: number }

const Bad = type.declare<Expected>().type({
	a: "string.numeric.parse",
	"b?": "number"
})

// the output must match Expected
const T = type.declare<Expected, { side: "out" }>().type({
	a: "string.numeric.parse",
	"b?": "number"
})
```
