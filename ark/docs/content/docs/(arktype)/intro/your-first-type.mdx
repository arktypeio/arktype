---
title: Your first type
description: Define a type with TypeScript syntax, compose it, and validate data with it.
---

If you already know TypeScript, you already know most of ArkType's syntax.

## Define

```ts
import { type } from "arktype"

const User = type({
	name: "string",
	platform: "'android' | 'ios'",
	"versions?": "(number | string)[]"
})

// { name: string; platform: "android" | "ios"; versions?: (number | string)[] }
type User = typeof User.infer
```

A key ending in `?` is optional, as in TypeScript. String literals like `'android'` need their own quotes inside the definition.

Definitions are checked by TypeScript, so a mistake is an error in your editor, with autocomplete to help fix it:

```ts
// @errors: 2322
const User = type({
	name: "strng"
})
```

## Compose

Suppose we want to move `platform` and `versions` from our original type to a new `device` property.

```ts
const User = type({
	name: "string",
	// nested definitions don't need to be wrapped
	device: {
		platform: "'android' | 'ios'",
		"versions?": "(number | string)[]"
	}
})
```

To decouple `device` from `User`, move it to its own type and reference it.

```ts
const Device = type({
	platform: "'android' | 'ios'",
	"versions?": "(number | string)[]"
})

const User = type({
	name: "string",
	device: Device
})
```

## Validate

Call a type with `unknown` data to get back either the validated data or an `ArkErrors` object describing every problem.

```ts
const User = type({
	name: "string",
	device: {
		platform: "'android' | 'ios'",
		"versions?": "(number | string)[]"
	}
})
// ---cut---
const out = User({
	name: "Alan Turing",
	device: {
		platform: "enigma",
		versions: [0, "1", 0n]
	}
})

if (out instanceof type.errors) {
	// ArkErrors: device.platform must be "android" or "ios" (was "enigma")
	//            device.versions[2] must be a number or a string (was a bigint)
	console.error(out.summary)
} else {
	// out is narrowed to the validated User
	console.log(`Hello, ${out.name}`)
}
```

Calling a type never throws for invalid data. Each problem is in `out.issues`, with its `path`, `code` and `message`; see [Errors](/docs/errors).

Where invalid data is a bug rather than something to handle, use `.assert`. It returns the validated data or throws a `TraversalError` describing the same problems.

```ts
const User = type({
	name: "string"
})
// ---cut---
// TraversalError: name must be a string (was missing)
const user = User.assert({})
```

You now know how to define a `Type` and use it to check your data at runtime.
