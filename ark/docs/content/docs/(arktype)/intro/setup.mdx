## Installation

<InstallationTabs />

```ts
import { type } from "arktype"

const User = type({
	name: "string",
	"age?": "number.integer >= 0"
})

// ArkErrors: age must be non-negative (was -1)
const out = User({ name: "Alan", age: -1 })
```

## Requirements

- TypeScript `>=5.1`, including TypeScript 7.
- An ESM project. ArkType is ESM-only, but a CommonJS project can `require` it on runtimes that support `require(esm)`, like Node `>=20.19` or `>=22.12`.

```json title="tsconfig.json"
{
	"compilerOptions": {
		"strict": true,
		"skipLibCheck": true,
		"exactOptionalPropertyTypes": true
	}
}
```

- [`strict`](https://www.typescriptlang.org/tsconfig#strict), or at least [`strictNullChecks`](https://www.typescriptlang.org/tsconfig#strictNullChecks), is required for inference to work.
- [`skipLibCheck`](https://www.typescriptlang.org/tsconfig#skipLibCheck) is recommended. It avoids harmless errors from differences between your config and ours (see [FAQ](/docs/faq#why-do-i-see-type-errors-in-an-arktype-package-in-node_modules)) and speeds up your editor.
- [`exactOptionalPropertyTypes`](https://www.typescriptlang.org/tsconfig#exactOptionalPropertyTypes) is recommended. It makes your inferred types match runtime behavior. ArkType rejects `undefined` for an optional key unless its value allows it, so without this flag, `typeof User.infer` accepts `{ age: undefined }` while `User` rejects it.

ArkType runs in Node, Deno, Bun, browsers and edge runtimes. Under a strict Content-Security-Policy, enable [`jitless`](/docs/configuration#jitless) so it never tries `new Function`, or [precompile](#precompile) your Types.

## Precompile

If your app is bundled, add [`@ark/aot`](/docs/precompile) to your bundler. Every Type you define is then compiled when you build into a standalone validator, so arktype's parser never ships and nothing is compiled at runtime:

<InstallationTabs pkg="@ark/aot" dev />

```ts title="vite.config.ts"
// @noErrors
import { precompile } from "@ark/aot/unplugin"
import { defineConfig } from "vite"

export default defineConfig({
	plugins: [precompile.vite()]
})
```

Your definitions don't change, and you can add it at any time. [Setup](/docs/precompile/setup) covers the other bundlers, test runners and Next.
