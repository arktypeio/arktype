## Install

<InstallationTabs />

<InstallationTabs pkg="@ark/aot" dev />

`arktype` is a dependency and `@ark/aot` a dev dependency. `arktype` defines and validates Types. [`@ark/aot`](/docs/precompile) precompiles them when you build, so arktype's parser never ships and nothing compiles at runtime. Skip it for a script or REPL with no build step: every Type works without it.

## Define a Type

```ts title="src/user.ts"
import { type } from "arktype"

export const User = type({
	name: "string",
	"age?": "number.integer >= 0"
})

const out = User({ name: "Alan", age: -1 })

if (out instanceof type.errors) console.error(out.summary)
```

<Tab value="Vite">

```ts title="vite.config.ts"
// @noErrors
import { precompile } from "@ark/aot/unplugin"

export default defineConfig({
	plugins: [precompile.vite()]
})
```

```js title="next.config.js"
				condition: { content: /arktype/ },

	}

```

## Run it

Build or start your dev server as you already do. `User` is now a standalone validator, and the program prints:

```
age must be non-negative
```

A precompiled error says what failed without printing the value, which arktype at runtime adds as `(was -1)`.

To see what the build makes of each definition without bundling, run:

```sh
npx arktype-precompile --check
```

```
src/user.ts:3:21  accepted
1 site in 2 files: 1 accepted (100.0%)
```

A definition the build can't precompile fails it, naming the file, the line and the fix. See [Troubleshooting](/docs/precompile/troubleshooting).

## Configure TypeScript

TypeScript `>=5.1`, including TypeScript 7, with:

```json title="tsconfig.json"
{
	"compilerOptions": {
		"strict": true,
		"skipLibCheck": true,
		"exactOptionalPropertyTypes": true
	}
}
```

- [`strict`](https://www.typescriptlang.org/tsconfig#strict), or at least [`strictNullChecks`](https://www.typescriptlang.org/tsconfig#strictNullChecks), is required for inference to work.
- [`skipLibCheck`](https://www.typescriptlang.org/tsconfig#skipLibCheck) is recommended. It avoids harmless errors from differences between your config and ours (see [FAQ](/docs/faq#why-do-i-see-type-errors-in-an-arktype-package-in-node_modules)) and speeds up your editor.
- [`exactOptionalPropertyTypes`](https://www.typescriptlang.org/tsconfig#exactOptionalPropertyTypes) is recommended. It makes your inferred types match runtime behavior. ArkType rejects `undefined` for an optional key unless its value allows it, so without this flag, `typeof User.infer` accepts `{ age: undefined }` while `User` rejects it.

ArkType is ESM-only, but a CommonJS project can `require` it on runtimes that support `require(esm)`, like Node `>=20.19` or `>=22.12`. TypeScript allows that `require` under `"module": "nodenext"` from 5.8, where `node16` reports TS1479. `@ark/aot` runs on Node 22.12 or later.

## Runtimes

ArkType runs in Node, Deno, Bun, browsers and edge runtimes like Cloudflare Workers. A precompiled validator never generates code, so it runs under a Content-Security-Policy that blocks `eval`. Without precompiling, ArkType validates without compiling where `new Function` is blocked; under a strict policy, enable [`jitless`](/docs/configuration#jitless) so it never tries `new Function`, which the policy would report.
