---
title: Morphs
description: Transform data as part of validation by piping it through functions and other Types.
---

Sometimes, data at the boundaries of your code needs more than validation before it's ready to use.

**Morphs** transform your data. You can **pipe** them before, after or between validators, and chain them to other morphs.

```ts
// Type<(In: string) => Out<object>>
const parseJson = type("string").pipe((s): object => JSON.parse(s))

// { ark: "type" }
const out = parseJson('{ "ark": "type" }')

// ArkErrors: must be a string (was an object)
const badOut = parseJson(out)
```

This is a good start, but what happens if we pass a string that isn't valid JSON?

```ts
const parseJson = type("string").pipe((s): object => JSON.parse(s))
// ---cut---

// Uncaught SyntaxError: Expected property name ☠️ // [!code error]
const badOut = parseJson('{ unquoted: "keys" }')
```

By default, ArkType assumes that if one of your morphs or narrows throws, you intend to crash. For a function you don't trust, use `pipe.try`, which turns what it throws into an error:

```ts
const parseJson = type("string").pipe.try((s): object => JSON.parse(s))

const out = parseJson('{ unquoted: "keys" }')

if (out instanceof type.errors) {
	// ArkErrors: must be valid according to an anonymous predicate (was aborted due to error:
	//                SyntaxError: Expected property name or '}' in JSON at position 2 (line 1 column 3)
	//            )
	console.error(out.summary)
}
```

A validated `object` still isn't very useful, though. Since a Type can be called like a function, it can be a step in a pipe too. For JSON, the built-in `string.json.parse` keyword does the parsing, and `.to` validates its output:

```ts
// .to is a sugared .pipe for a single parsed output validator
const parseJson = type("string.json.parse").to({
	name: "string",
	version: "string.semver"
})

const out = parseJson('{ "name": true, "version": "v2.0.0" }')

if (out instanceof type.errors) {
	// ArkErrors: name must be a string (was boolean)
	//            version must be a semantic version (see https://semver.org/) (was "v2.0.0")
	console.error(out.summary)
} else {
	// { name: string; version: string }
	console.log(`${out.name}:${out.version}`)
}
```

<Callout type="warn" title="Morphs receive your data, not a copy">
	A morph is passed the validated value itself. If it mutates its argument, it
	mutates the caller's data, so return a new value instead.
</Callout>

```ts
const addTag = type({ tags: "string[]" }).pipe(o => ({
	...o,
	tags: [...o.tags, "new"]
}))
```

When you're ready to ship, [precompile](/docs/precompile) your Types: the same definitions, compiled when you build into standalone validators that carry only the checks they need.
