## ArkErrors

A Type called with invalid data returns `ArkErrors`, which holds one `ArkError` for each path that failed:

```ts
const User = type({
	name: "string",
	age: "number >= 0"
})

const out = User({ name: 5, age: -1 })

if (out instanceof type.errors) {
	// age must be non-negative (was -1)
	// name must be a string (was a number)
	console.error(out.summary)

	// ["age must be non-negative (was -1)",
	//  "name must be a string (was a number)"]
	out.issues.map(error => error.message)

	// { age: ["must be non-negative (was -1)"],
	//   name: ["must be a string (was a number)"] }
	out.flatProblemsByPath
}
```

`ArkErrors` is iterable and has a `length`, but it isn't an array. Index it or call array methods through `issues`.

| member                             | what it is                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| `summary`, `message`, `toString()` | every error's message, one per line                                                              |
| `issues`                           | an array with one `ArkError` per path, in the order each path first failed                       |
| `byPath`                           | an object mapping each path's `propString` to its `ArkError`                                     |
| `flatByPath`                       | like `byPath`, but each value is an array, with an `intersection` split into its errors          |
| `flatProblemsByPath`               | like `flatByPath`, but with each error's `problem`                                               |
| `byAncestorPath`                   | each failed path and its ancestors, with `""` for the root, mapped to every error at or below it |
| `count`                            | how many errors were added, more than `length` when several failed at one path                   |
| `toJSON()`                         | an array of each error's `toJSON()`                                                              |
| `toLocaleString(locale?)`          | the summary in a [locale](/docs/i18n#rendering-in-a-locale)                                      |
| `throw()`                          | throws a [`TraversalError`](#traversalerror)                                                     |
| `toTraversalError()`               | returns that `TraversalError` instead of throwing it                                             |

## ArkError

Each `ArkError` describes what failed at one path:

```ts
const out = type({ age: "number >= 0" })({ age: -1 })

if (out instanceof type.errors) {
	const error = out.issues[0]

	error.code // "min"
	error.path // ["age"]
	error.propString // "age"
	error.data // -1
	error.expected // "non-negative"
	error.actual // "-1"
	error.problem // "must be non-negative (was -1)"
	error.message // "age must be non-negative (was -1)"

	// narrow by code to read its own fields
	if (error.hasCode("min")) error.rule // 0
}
```

Its message is built from parts: `message` puts the path before `problem`, which reads "must be `expected` (was `actual`)". You can [configure each part](/docs/configuration#errors).

An error also has `meta`, the metadata of the Type that failed, and usually a `description`. Like `ArkErrors`, it has `toJSON()` and `toLocaleString(locale?)`.

When several checks fail at one path, they are merged into one error with the code `intersection`. Its `flat` getter, and `flatByPath`, split it back up:

```ts
const out = type({ n: "number % 2 >= 2" })({ n: 1 })

if (out instanceof type.errors) {
	// n (1) must be...
	//   ◦ even
	//   ◦ at least 2
	console.error(out.summary)

	// { n: ["must be even (was 1)", "must be at least 2 (was 1)"] }
	out.flatProblemsByPath
}
```

## Error codes

An error's `code` tells you its other fields:

| code                                    | fields                                                                                                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `domain`                                | `domain`, like `"string"`                                                                                                                                  |
| `unit`                                  | `unit`, the expected value                                                                                                                                 |
| `proto`                                 | `proto`, the expected constructor                                                                                                                          |
| `min`, `max`                            | `rule`, and `exclusive` when the bound is exclusive                                                                                                        |
| `minLength`, `maxLength`, `exactLength` | `rule`                                                                                                                                                     |
| `divisor`                               | `rule`                                                                                                                                                     |
| `pattern`                               | `rule` (the regex source) and `flags`                                                                                                                      |
| `before`, `after`                       | `rule`, a `Date`                                                                                                                                           |
| `predicate`                             | `predicate` when a narrow returns `false`; `morph` and what it threw as `cause` for `pipe.try`; `meta.keyword` and sometimes `cause` for a keyword's parse |
| `required`                              | `missing`, the missing value's type; `valueMeta`, its meta; and `missingValueDescription`, its English description                                         |
| `undeclared`                            | none; its `data` is the value of a key `"+": "reject"` disallows                                                                                           |
| `discriminant`                          | `discriminantKind`, `cases`, `onKey` and `absent`                                                                                                          |
| `union`                                 | `errors`, one per branch                                                                                                                                   |
| `intersection`                          | `errors`, one per check that failed at the path                                                                                                            |

Each also has `data` and `path`, and `meta` unless `ctx` or `pipe.try` raised it. Built-in keywords with their own text, like `string.email`, set `meta.keyword` to their name.

`discriminant` is a miss of a union ArkType checks by switching on a domain or a literal value: branches with different domains, like `number | null`, three or more literals, like `"a" | "b" | "c"`, or objects with a discriminant key. Its `data` is the discriminant's value, and `cases` lists the values or domains it expected. Other unions, including two literals like `"a" | "b"`, report `union`:

```ts
const Shape = type({ kind: "'circle'", r: "number" }).or({
	kind: "'square'",
	side: "number"
})

const out = Shape({ kind: "triangle" })

if (out instanceof type.errors) {
	const error = out.issues[0]

	// kind must be "circle" or "square" (was "triangle")
	error.message

	// ["circle", "square"]
	if (error.hasCode("discriminant")) error.cases
}
```

## TraversalError

`.assert`, `.from` and `ArkErrors.throw()` throw a `TraversalError`, which extends `Error`. A single error's message is its summary. Several are listed on their own lines after a leading newline:

```ts
import { type, TraversalError } from "arktype"

try {
	type({ a: "string", b: "number" }).assert({ a: 1, b: "x" })
} catch (e) {
	if (e instanceof TraversalError) {
		// "\n  • a must be a string (was a number)\n  • b must be a number (was a string)"
		e.message

		// the ArkErrors, for structured access
		e.arkErrors.flatProblemsByPath
	}
}
```

`arkErrors` is non-enumerable, so loggers that print an error's own properties skip it.

## ParseError

A `ParseError` is thrown when a definition is invalid, as the Type is created rather than when it validates. TypeScript reports the same mistakes in your editor, so you'll usually see one only for definitions TypeScript can't check, like strings built at runtime:

```ts
import { ParseError, type } from "arktype"

const def: string = "string | numbr"

try {
	type.raw(def)
} catch (e) {
	// ParseError: 'numbr' is unresolvable
	if (e instanceof ParseError) console.error(e.message)
}
```
