## string

### keywords [#string-keywords]

Reference a keyword anywhere a definition is expected:

```ts
const User = type({
	email: "string.email",
	ids: "string.uuid.v4[]"
})
```

<StringKeywordTable />

Every keyword, including those for other types, is listed on the [keywords](/docs/keywords) page.

### literals [#string-literals]

Quote a string inside a definition to allow exactly that string. Single and double quotes are equivalent:

```ts
const Literals = type({
	singleQuoted: "'typescript'",
	doubleQuoted: '"arktype"'
})
```

### patterns [#string-patterns]

A regex literal requires the string to match it. Like a `RegExp`, it is unanchored unless you anchor it with `^` and `$`.

<SyntaxTabs>
	<SyntaxTab string>

```ts
const AToZ = type("/^a.*z$/")

// ArkErrors: must be matched by ^a.*z$ (was "abc")
AToZ("abc")
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
const AToZ = type.string.matching(/^a.*z$/)

// ArkErrors: must be matched by ^a.*z$ (was "abc")
AToZ("abc")
```

    </SyntaxTab>

</SyntaxTabs>

A `RegExp` works as a definition too, e.g. `type({ code: /^a.*z$/ })`.

Regex literals are typed with [ArkRegex](/docs/regex), so a pattern that constrains the string's shape narrows the inferred type:

```ts
// Type<string>
const Hex = type("/^[0-9a-fA-F]+$/")

// Type<`${number}.${number}.${number}`>
const Semver = type("/^(\\d+)\\.(\\d+)\\.(\\d+)$/")
```

#### e(x)ec mode

Prefix a regex literal with `x` to transform the string into the result of `RegExp.prototype.exec`. The output is the match, not the string, and its capture groups are typed:

```ts
const User = type({
	birthday: "x/^(?<month>\\d{2})-(?<day>\\d{2})-(?<year>\\d{4})$/"
})

const data = User.assert({ birthday: "05-21-1993" })

data.birthday.groups.month // "05"
data.birthday.groups.year // "1993"
```

### lengths [#string-lengths]

Constrain a string's length with `>`, `>=`, `<`, `<=`, `==` or `!=`:

<SyntaxTabs>
	<SyntaxTab string>

```ts
const Bounded = type({
	nonEmpty: "string > 0",
	atMost10: "string <= 10",
	exactly5: "string == 5"
})
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
const Bounded = type({
	nonEmpty: type.string.moreThanLength(0),
	atMost10: type.string.atMostLength(10),
	exactly5: type.string.exactlyLength(5)
})
```

    </SyntaxTab>

</SyntaxTabs>

A range sets both bounds at once, each inclusive or exclusive:

<SyntaxTabs>
	<SyntaxTab string>

```ts
// 4 to 6 digits
const Pin = type("4 <= string.digits <= 6")

// ArkErrors: must be at least length 4 (was 3)
Pin("123")
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
// 4 to 6 digits
const Pin = type.keywords.string.digits.atLeastLength(4).atMostLength(6)

// ArkErrors: must be at least length 4 (was 3)
Pin("123")
```

    </SyntaxTab>

</SyntaxTabs>

## number

`number` rejects `NaN`, `Infinity` and `-Infinity`. Allow them in one type with the `number.NaN`, `number.Infinity` and `number.NegativeInfinity` keywords:

```ts
const MaybeInfinite = type("number | number.Infinity | number.NegativeInfinity")
```

To allow them everywhere, configure [`numberAllowsNaN`](/docs/configuration#numberallowsnan) or [`numberAllowsInfinity`](/docs/configuration#numberallowsinfinity).

### ranges [#number-ranges]

Constrain a number with `>`, `>=`, `<` or `<=`:

<SyntaxTabs>
	<SyntaxTab string>

```ts
const Bounded = type({
	positive: "number > 0",
	atMost5: "number <= 5"
})
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
const Bounded = type({
	positive: type.number.moreThan(0),
	atMost5: type.number.atMost(5)
})
```

    </SyntaxTab>

</SyntaxTabs>

A range sets both bounds at once, each inclusive or exclusive:

<SyntaxTabs>
	<SyntaxTab string>

```ts
const Percentage = type("0 <= number <= 100")

// ArkErrors: must be at most 100 (was 101)
Percentage(101)
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
const Percentage = type.number.atLeast(0).atMost(100)

// ArkErrors: must be at most 100 (was 101)
Percentage(101)
```

    </SyntaxTab>

</SyntaxTabs>

`!=` excludes one value:

```ts
const NonZero = type("number != 0")

// ArkErrors: must be other than 0 (was 0)
NonZero(0)
```

### literals [#bigint-literals]

Add the suffix `n` to a [number literal](/docs/primitives#number-literals) to allow exactly that `bigint`:

```ts
const Literals = type({
	bigint: "1337n"
})
```

A [unit expression](/docs/expressions#unit) like `type.unit(1337n)` does the same.

## undefined

`"undefined"` allows exactly `undefined`, usually in a [union](/docs/expressions#union):

<SyntaxTabs>
	<SyntaxTab string>

```ts
const MyObj = type({
	requiredKey: "number | undefined",
	"optionalKey?": "number | undefined"
})
```

    </SyntaxTab>

    <SyntaxTab fluent>

```ts
const MyObj = type({
	requiredKey: type.number.or(type.undefined),
	optionalKey: type.number.or(type.undefined).optional()
})
```

    </SyntaxTab>

</SyntaxTabs>

<Callout type="warn" title="Allowing undefined does not make a key optional">

Like in TypeScript, a required key that allows `undefined` must still be present:

```ts
const MyObj = type({
	key: "number | undefined"
})

// { key: undefined }
MyObj({ key: undefined })

// ArkErrors: key must be a number or undefined (was missing)
MyObj({})
```

</Callout>
