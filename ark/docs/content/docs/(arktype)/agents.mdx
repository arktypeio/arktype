## Skill

The ArkType [skill](https://github.com/arktypeio/arktype/blob/main/ark/type/skills/arktype/SKILL.md) tells agents when to reach for ArkType, how its syntax maps to TypeScript, and which mistakes to avoid. Add it to your project with:

```bash
npx skills add arktypeio/arktype
```

This installs the skill from the repository's default branch, which tracks the latest release. The `arktype` package also includes the skill at `skills/arktype/SKILL.md`, so tools like [skills-npm](https://github.com/antfu/skills-npm) can link the copy that matches your installed version.

## Docs as Markdown

Every page of these docs is available as Markdown by adding `.md` to its URL, e.g. [/docs/intro/setup.md](https://arktype.io/docs/intro/setup.md). The buttons under each page's title copy it or open it in Claude, ChatGPT or Cursor.

[/llms.txt](https://arktype.io/llms.txt) is an index of every page, with a link to its Markdown and a one-line description, following the [llms.txt](https://llmstxt.org) convention. [/llms-full.txt](https://arktype.io/llms-full.txt) has the full text of every ArkType page in one file. Attest's docs are at [/docs/attest/llms.txt](https://arktype.io/docs/attest/llms.txt) and ArkRegex's at [/docs/regex/llms.txt](https://arktype.io/docs/regex/llms.txt).

## Precompile

When an agent runs your local dev, a build step costs it a loop it's good at: build, read the error, fix, rebuild. So [precompiling](/docs/precompile) costs little, and it ships every Type as a standalone validator.

Each problem the build reports names the file, line and column, what it couldn't do, why, and how to fix it:

```
src/forms.ts:14:19  type(`string <= ${limit}`) cannot be precompiled
  `limit` is a parameter of makeField (src/forms.ts:12:22); its value is known only at runtime
  Standalone builds construct every Type at build time. Make it static, or build with runtime: "arktype".
```

`npx arktype-precompile --check "src/**/*.ts"` lists every such problem at once without bundling, and [shadow mode](/docs/precompile/advanced#shadow-mode) fails a test wherever a precompiled validator would behave otherwise than arktype. [Troubleshooting](/docs/precompile/troubleshooting) lists the fix for each report.

## AGENTS.md

If your project has an `AGENTS.md` or `CLAUDE.md`, a line like this keeps agents on ArkType when they add validation:

```
Validate untrusted input with ArkType. Docs: https://arktype.io/llms.txt
```

If you precompile, add:

```
ArkType definitions are precompiled when the app builds. Fix each precompile error as its hint says; don't set allowUnsafe to get past one.
```

## Building agents

ArkType types are [Standard Schemas](/docs/standard-schema) that can also produce JSON Schema, so libraries that need both accept them directly. For example, the [MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/v2/advanced/schema-libraries) (`@modelcontextprotocol/server`) takes an ArkType type as a tool's `inputSchema` as-is. It derives the JSON Schema the model sees from it, and validates the model's arguments before your handler runs:

```ts
// ---cut-start---
declare const server: {
	registerTool(
		name: string,
		config: { description: string; inputSchema: type.Any },
		handler: (args: { name: string; times?: number }) => unknown
	): void
}
// ---cut-end---
// server is an McpServer from @modelcontextprotocol/server
server.registerTool(
	"greet",
	{
		description: "Greet someone by name",
		inputSchema: type({ name: "string", "times?": "1 <= number.integer <= 5" })
	},
	async ({ name, times }) => ({
		content: [{ type: "text", text: `Hello, ${name}! `.repeat(times ?? 1) }]
	})
)
```

Calling `greet` with `times: 99` returns an error result to the model with ArkType's message, `times must be at most 5 (was 99)`, so it knows what to fix.
