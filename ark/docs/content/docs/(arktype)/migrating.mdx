title: Migrating
description: Migrate a project from Zod with one prompt, or convert schemas from Zod, Valibot, TypeBox, Yup, Joi, Effect Schema and JSON Schema to ArkType by hand, and the defaults that differ between them.
---

Add the [ArkType skill](/docs/agents#skill) to your project:

```bash
npx skills add arktypeio/arktype
```

Then ask your agent:

```
Migrate this project from Zod to ArkType.
```

The skill includes this page, and your agent works through [Migrating a project](#migrating-a-project): it converts each schema where it is, keeping what it accepts, rejects and returns, updates the code that calls it and swaps integrations like `zodResolver`. Before removing `zod`, it compares each schema your tests don't cover with its Zod original on the same inputs, then runs your typecheck and tests. Where a dependency accepts only Zod, like the MCP SDK before v2, it keeps Zod for that call. Its summary lists anything that still behaves differently, like error message text.

To [precompile](/docs/precompile) in the same pass, ask for both:

```
Migrate this project from Zod to ArkType and precompile it.
```

To convert by hand, start with the example below, then the [Zod table](#zod) and [Defaults that differ](#defaults-that-differ).

## Zod side by side

A Zod schema and its ArkType equivalent:

```ts
// ---cut-start---
declare const data: unknown
// ---cut-end---
import { z } from "zod"

const User = z.object({
	name: z.string().min(1),
	email: z.email(),
	age: z.number().int().nonnegative().optional(),
	role: z.enum(["admin", "member"]).default("member")
})

type User = z.infer<typeof User>

const result = User.safeParse(data)

if (!result.success) console.error(result.error.issues)
```

```ts
// ---cut-start---
declare const data: unknown
// ---cut-end---
import { type } from "arktype"

const User = type({
	// z.object() removes undeclared keys
	"+": "delete",
	name: "string >= 1",
	email: "string.email",
	// .optional() accepts undefined too
	"age?": "number.integer >= 0 | undefined",
	role: "'admin' | 'member' = 'member'"
})

type User = typeof User.infer

const out = User(data)

if (out instanceof type.errors) console.error(out.issues)
```

`.parse(data)` is `User.assert(data)`. The [Zod table](#zod) maps the rest of the API, and [Defaults that differ](#defaults-that-differ) lists what to write where the two libraries' defaults disagree, like `"+": "delete"` above. One the example leaves as is: Zod also applies `role`'s default when the key is present as `undefined`, which ArkType rejects.

## Zod

Zod Mini spells most methods as functions, so `z.optional(z.string())` maps like `z.string().optional()`, and `z.string().check(z.minLength(1))` like `z.string().min(1)`.

| `z.bigint()`, `z.symbol()`, `z.undefined()`, `z.void()` | `"bigint"`, `"symbol"`, `"undefined"`, `"undefined"`                                 |
| `z.unknown()`, `z.any()`, `z.never()`                   | `"unknown"`, `"unknown.any"`, `"never"`                                              |

| `z.enum(["a", "b"])`                                    | `"'a' \| 'b'"` or `type.enumerated("a", "b")`                                        |
| `z.nativeEnum(E)`, `z.enum(E)`                          | `type.valueOf(E)`                                                                    |
| `z.object({ ... })`                                     | `type({ ... })`, nested objects as plain objects                                     |
| `.optional()` on a property                             | `"key?": "T \| undefined"`                                                           |

| `.catchall(T)`                                          | `"[/^(?!a$\|b$)/]": T`, `a` and `b` the declared keys                                |

| `.describe(text)`, `.meta({ title })`                   | a comment or `.configure({ title: text })`                                           |

## Defaults that differ

| Behavior                                      | ArkType            | Zod                | Valibot  | TypeBox `Value.Check` | Yup                  | Joi                       | Effect Schema |
| --------------------------------------------- | ------------------ | ------------------ | -------- | --------------------- | -------------------- | ------------------------- | ------------- |
| Undeclared object keys                        | kept               | removed            | removed  | allowed               | kept                 | rejected                  | removed       |
| Optional key present with the value undefined | rejected           | accepted           | accepted | accepted              | accepted             | accepted                  | accepted      |
| Default applied when the value is undefined   | no, only if absent | yes                | yes      | only `Value.Default`  | yes                  | yes                       | yes           |
| Converts input types, e.g. `"12"` to `12`     | only when parsing  | only in `z.coerce` | no       | only `Value.Convert`  | yes, unless strict   | yes, unless convert false | no            |
| `number` accepts `Infinity`                   | no                 | v4: no, v3: yes    | yes      | no                    | yes                  | no                        | yes           |
| `number` accepts `NaN`                        | no                 | no                 | no       | no                    | no                   | no                        | yes           |
| An array where an object is expected          | accepted           | rejected           | accepted | rejected              | rejected             | rejected                  | rejected      |
| Empty string for a plain string               | accepted           | accepted           | accepted | accepted              | rejected if required | rejected                  | accepted      |

What to write when the old behavior matters:

```ts
// remove undeclared keys like Zod, Valibot and Effect, for this object only
const Stripped = type({ "+": "delete", name: "string" })

// reject them like Joi or Zod's .strict()
const Strict = type({ "+": "reject", name: "string" })

// accept an explicit undefined as well as a missing key
const Patch = type({ "nickname?": "string | undefined" })

// apply a default when the key is missing or undefined
const Settings = type({
	theme: type("'light' | 'dark' | undefined")
		.pipe(v => v ?? "light")
		.default(undefined)
})

// allow non-finite numbers
const Measurement = type(
	"number | number.Infinity | number.NegativeInfinity | number.NaN"
)
```

`"+"` applies to its own object, not to nested ones, and `.merge()` takes it from the object merged in, so repeat it there. To remove undeclared keys everywhere, as Zod does, set `onUndeclaredKey: "delete"` with `configure` from `arktype/config`, in a file imported before anything imports `arktype`.

Either way, an object that deletes keys transforms its input, so a union of such objects needs a key that tells them apart, like a literal `type`. Without one, data with both objects' keys could come out as either, so the union throws a `ParseError`. Where the old schema has no such key, delete outside the union. The result keeps every key either object declares, where Zod keeps only those of the first object that matches:

```ts
// z.union([z.object({ uri, text }), z.object({ uri, blob })])
const Contents = type({ "+": "ignore", uri: "string", text: "string" })
	.or({ "+": "ignore", uri: "string", blob: "string" })
	.to({ "+": "delete", uri: "string", "text?": "string", "blob?": "string" })
```

With `"delete"` or `"reject"`, from `"+"` or `configure`, an object's undeclared keys are `never`, so `.and()` with an object that has other keys throws. Add keys with `.merge()`.

## Semantics to check

**Transforms run in order.** `.pipe(fn)` transforms after validation, `.to(definition)` validates the result, and a `.narrow()` after a `.pipe()` sees the transformed value, like Zod's `.transform().refine()`. A narrow on an object whose properties transform sees the transformed properties.

```ts
// Zod: z.string().transform(s => s.length).refine(n => n > 2)
const Length = type("string")
	.pipe(s => s.length)
	.narrow(n => n > 2)

// Zod: z.preprocess(v => (typeof v === "string" ? v.split(",") : v), z.array(z.string()))
const Tags = type("string | string[]")
	.pipe(v => (typeof v === "string" ? v.split(",") : v))
	.to("string[]")
```

**Coercion is a parse.** ArkType never converts a value unless the definition says so, so write the conversion the old library did. `string.numeric.parse`, `string.integer.parse`, `string.date.parse`, `string.json.parse` and `string.url.parse` accept only strings, and accept fewer of them than `Number()` or `new Date()`:

```ts
// z.coerce.number(), which is Number(value) for any input
const Count = type("unknown").pipe(Number).to("number")

// z.coerce.number().int().positive().default(8080) in an object
const Server = type({
	port: type("unknown").pipe(Number).to("number.integer > 0").default(8080)
})

// z.coerce.date(), which is new Date(value) for any input, so null is 1970-01-01
const When = type("unknown")
	.pipe(
		v => new Date(v instanceof Date || typeof v === "string" ? v : Number(v))
	)
	.to("Date")

// stricter, for strings only: rejects " 1", "0x10" and ""
const Page = type("string.numeric.parse")

// z.stringbool() accepts "true", "1", "yes", "on" and their opposites; write the set you need
const Flag = type("'true' | 'false'").pipe(s => s === "true")
```

**Refinements with a path or several errors.** A `.narrow()` returns `true` or calls `ctx.reject()`, which takes a `path` and a full `message`. To report several errors, call `ctx.error()` for each, then return `true`:

```ts
// Zod: .superRefine((d, ctx) => ctx.addIssue({ code: "custom", message: "...", path: ["end"] }))
const Range = type({ start: "number", end: "number" }).narrow(
	(d, ctx) =>
		d.start <= d.end ||
		ctx.reject({ message: "end must not be before start", path: ["end"] })
)
```

**Fallbacks.** ArkType has no `.catch()`. Zod's `.catch(x)` returns `x` for any invalid input, so validate inside a `.pipe()` and return `x` on errors. The default covers a missing key, which `.catch()` also replaces:

```ts
const Count = type("number")

// z.object({ count: z.number().catch(0) })
const Settings = type({
	count: type("unknown")
		.pipe(v => {
			const out = Count(v)
			return out instanceof type.errors ? 0 : out
		})
		.default(0)
})
```

**Discriminated unions are plain unions.** ArkType finds the discriminant itself, so `z.discriminatedUnion("type", [A, B])`, `v.variant("type", [...])` and `Schema.Union(A, B)` are `A.or(B)`, or `"A | B"` in a scope.

**Recursion needs no annotation.** Replace `z.lazy`, `v.lazy`, `Type.Recursive`, `yup.lazy`, `Joi.link` and `Schema.suspend` with a scope, or `this` for a type that refers to itself:

```ts
const Category = type({ name: "string", subcategories: "this[]" })

const types = scope({
	Json: "string | number | boolean | null | Json[] | JsonObject",
	JsonObject: { "[string]": "Json" },
	Filter: { "[string]": "Json | Filter" }
}).export()
```

Delete the hand-written TypeScript type that `z.lazy` needed; `typeof types.Filter.infer` replaces it.

**Composing objects.** `.merge()` replaces keys like Zod's `.extend()`, `v.object({ ...a.entries })` or `Type.Composite`. `.and()` intersects, and throws when a key's types conflict. `.pick()`, `.omit()`, `.partial()`, `.required()` and `.keyof()` keep their names.

**Records with literal keys.** `Record<"a" | "b", T>` must be written as named keys, `{ a: T, b: T }` (add `?` for Zod v3, whose enum-keyed records are partial). An index signature like `"[string]": "number"` applies to every key, including declared ones. Zod's `.catchall(T)` applies only to undeclared keys, so leave the declared ones out of a regex index signature: `z.object({ name: z.string() }).catchall(z.number())` is `type({ name: "string", "[/^(?!name$)/]": "number" })`.

**Brands.** `.brand("UserId")` or `"string#UserId"` infers `Brand<string, "UserId">`, which is not assignable to or from the old library's brand type. Change code that names the old brand type to `typeof UserId.infer`.

**Errors.** Errors are values: `T(data)` returns the data or an `ArkErrors`, and `T.assert(data)` throws. To change a message, `.describe("a strong password")` gives `must be a strong password (was ...)`, and `.configure({ message: "Choose a stronger password" })` replaces the whole message. Zod's and Valibot's `description` is documentation, but ArkType's `.describe()` is what errors say the value must be, so keep documentation in a comment or `.configure({ title })`.

**Dates and formats.** `z.string().datetime()` rejects offsets and date-only strings unless configured; `string.date.iso` accepts both. In JSON Schema, `format` is an annotation and validates nothing unless the validator, like ajv with `ajv-formats`, checks it; `string.email` always validates.

**Synchronous only.** ArkType doesn't await. Move an async `refine`, Yup `test` or Joi `external` out of the schema and run it after validation.

## Migrating a project

To move a whole project off Zod, or another library below, work through it in this order.

1. **Take stock.** Find every import of the old library (`zod`, `zod/v4`, `zod/mini`) and of packages built on it, like `@hookform/resolvers/zod` or `zod-to-json-schema`, and every use of the schemas, including files that call `.safeParse()` or read `.shape` without importing the library. Run the project's `typecheck` and `test` scripts once, so you know what passes before you start. If `package.json` has no `test` script, step 6 is how you'll check behavior.
2. **Convert each schema in place.** Keep its name, its file and what it takes and returns, so imports and call sites keep working: a `.transform()` stays in the schema as a `.pipe()`, not in its callers. `z.infer<typeof X>` and `z.output` become `typeof X.infer`, and `z.input` becomes `typeof X.inferIn`.
3. **Keep behavior identical.** The migrated schemas should accept, reject and return what the old ones did. These rules are for Zod, and [Defaults that differ](#defaults-that-differ) has them for the other libraries:
   - `z.object()` removes undeclared keys, and so should the migrated objects, even where the code reads only declared keys, since parsed data often reaches a database or a response whole. Call `configure({ onUndeclaredKey: "delete" })` from `arktype/config` in one file, like `src/arktype.config.ts`, and import it first in every file that creates a Type, so it applies whichever file loads first, tests included. If the project [precompiles](/docs/precompile), also name that file as the build's `config` in [`ark.json`](/docs/precompile/setup#ark-json), which the CLI and test drivers read as the bundler does. Then `.passthrough()` and `z.looseObject()` become `"+": "ignore"`, and `.strict()` becomes `"+": "reject"`.
   - Without that setting, write `"+": "delete"` in every object instead, nested ones included. `.merge()` takes `"+"` from the object merged in, so write `.merge({ "+": "delete", ... })`; with the global setting, merged objects keep deleting.
   - A union of such objects throws a `ParseError` saying it's indeterminate unless a key tells them apart. Follow [Defaults that differ](#defaults-that-differ) for it, and keep the global setting: `"+": "ignore"` belongs only on the union's branches.
   - `.optional()` also accepts `undefined`, so write `"key?": "T | undefined"`. Before Zod 4.4, any key whose schema accepts `undefined` may be missing, so a `z.unknown()` key is `"key?": "unknown"`; from 4.4, only `.optional()` and defaults let a key be missing, so it stays `key: "unknown"`. Check the version the project installs. In Zod 4, `.default(x).optional()` still fills in `x`, so it's `key: T.default(x)`.
   - `z.any()` is `"unknown.any"`, or `"key?": "unknown.any"` as a key before Zod 4.4. It infers `any` as Zod's did, so refinements that read its properties type-check without casts.
   - Translate coercions and refinements literally, as in [Coercion is a parse](#semantics-to-check). `z.coerce.number()` takes any input, `null` included, so its input stays `"unknown"`, in a tool's input schema too. Keywords like `string.numeric.parse` reject inputs Zod accepted, like `" 1"`, so suggest them rather than substituting them. A `.refine()` after a `.transform()` is a `.narrow()` after a `.pipe()`: `.to("number > 0")` would also check the type, and `number` rejects `Infinity` and `NaN`. An object's `.refine()` stays on that object as a `.narrow()`, not in a second schema. Zod 4 runs it even when a key fails a check like `.min()` or `.regex()`, though not when one is missing or of the wrong type, so its issue joins theirs; a narrow runs only once every key is valid.
   - Zod 4.6's `.url()` trims its input, accepts what `URL.canParse` accepts and returns the trimmed string without tabs or line breaks; Zod 4.1's returned it as given. `string.url` checks with `URL.canParse` too but doesn't trim, so where the output is kept, write `type("string").pipe(s => s.trim().replace(/[\t\n\r]/g, "")).to("string.url")`.
   - `string.email` and Zod 4's `z.email()` disagree on some addresses: Zod rejects `a..b@x.co` and `.a@x.co` and accepts `a'b@x.co`, and ArkType does the opposite. Where that matters, keep Zod's pattern as a regex.
   - Keep custom messages. `.min(1, "Name is required")` becomes `type("string >= 1").configure({ message: "Name is required" })`.
4. **Update call sites.**
   - `X.parse(data)` becomes `X.assert(data)`, which throws.
   - `X.safeParse(data)` becomes `const out = X(data)`, then check `out instanceof type.errors`. `parseAsync` and `safeParseAsync` become the same, since ArkType is synchronous.
   - `ZodError` becomes `type.errors`, and `instanceof ZodError` becomes `instanceof type.errors`. Its `issues` keep their `path` and `message`, though a message names its path, like `email must be an email address (was "x")`, where Zod's says `Invalid email address`. `z.prettifyError(error)` becomes `out.summary`. `X.assert` throws a `TraversalError`, whose `arkErrors` holds them.
   - `error.flatten()` and `z.flattenError(error)` group messages by the first key of their path, so `tags[0]`'s are under `tags`. Group `out.issues` the same way, which also works in a [precompiled](/docs/precompile) build, where `flatByPath` isn't available:
   - Don't add casts or `any`, not even `as unknown`. A helper typed with `z.ZodTypeAny` or `z.ZodSchema` takes `type.Any`. To keep the output type, use `<T extends type.Any>(schema: T): T["infer"]`, not `type.Any<t>`. A function that builds a schema from another becomes a generic, like `type("<t>", { data: "t" })`.

```ts
// ---cut-start---
declare const out: type.errors
// ---cut-end---
// error.flatten() or z.flattenError(error)
const formErrors: string[] = []
const fieldErrors: Record<string, string[]> = {}
for (const issue of out.issues) {
	if (issue.path.length === 0) formErrors.push(issue.message)
	else (fieldErrors[String(issue.path[0])] ??= []).push(issue.message)
}
```

5. **Swap integrations.** Most accept an ArkType type directly, through [Standard Schema](/docs/standard-schema):

| With Zod                                                    | With ArkType                                                                                                                                        |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `zodResolver(schema)` (react-hook-form)                     | `standardSchemaResolver(schema)` from `@hookform/resolvers/standard-schema`                                                                         |
| tRPC `.input(schema)`, `@t3-oss/env-*`, TanStack Form       | the same call, given the ArkType type                                                                                                               |
| AI SDK 6 `tool({ inputSchema })`, MCP SDK v2 `registerTool` | the same call, given the ArkType type, which also supplies the JSON Schema                                                                          |
| AI SDK 5 `tool({ inputSchema })`                            | `jsonSchema<typeof T.infer>(T.toJsonSchema(), { validate })`, where `validate` returns `{ success: true, value }` or `{ success: false, error }`    |
| `zValidator` from `@hono/zod-validator`                     | `sValidator` from `@hono/standard-validator`, whose hook's `result.error` is the issue array, not `{ issues }`, and a path segment may be `{ key }` |
| `@hono/zod-openapi`                                         | `hono-openapi`: `describeRoute`, `validator` and `resolver`                                                                                         |
| `zod-to-json-schema`, `z.toJSONSchema(schema)`              | `schema.toJsonSchema()`                                                                                                                             |
| `@asteasolutions/zod-to-openapi`                            | `schema.toJsonSchema({ target: "openapi-3.0" })` for each Schema Object in your OpenAPI document; see below                                         |
| `drizzle-zod`                                               | `drizzle-arktype`                                                                                                                                   |
| a library that accepts only Zod                             | keep Zod for that call, and say so                                                                                                                  |

With npm, `@hookform/resolvers`, `@t3-oss/env-core` and other packages that peer on `arktype@^2` make installs fail with `ERESOLVE` until they widen their range. For each package the error names, add an [override](/docs/upgrading#npm-refuses-packages-that-peer-on-arktype-2) rather than passing `--force` or `--legacy-peer-deps`.

Without casts:

- `toJsonSchema()` returns a `JsonSchema`, the type to give the document's Schema Objects (`import type { JsonSchema } from "arktype"`). Build path and query parameters from an object type's `.props`, which lists each key, whether it's required, and its Type.
- A `fallback` declared apart from the `toJsonSchema()` call is a `ToJsonSchema.FallbackOption` (`import type { ToJsonSchema } from "arktype"`).
- The MCP SDK finds a prompt argument's completer through Zod's `.shape`, so give `argsSchema` one, as below.

```ts
import { completable } from "@modelcontextprotocol/server"
import { type } from "arktype"

const Args = type({ language: "string" })
const argsSchema = {
	"~standard": Args["~standard"],
	shape: {
		language: completable({ "~standard": type("string")["~standard"] }, value =>
			["typescript", "python"].filter(l => l.startsWith(value))
		)
	}
}
```

6. **Compare with the originals while Zod is still installed.** The project's tests check the schemas they use. Check the rest directly, and every schema if there's no `test` script: in a scratch file, import each original from a copy of its file (`git show HEAD:src/schemas.ts > scratch/schemas.zod.ts`) and its conversion, call both on the same inputs and compare which they accept and what they return. Use the project's fixtures or sample data where it has them, plus each case [Defaults that differ](#defaults-that-differ) lists: a missing key, a key present as `undefined`, an undeclared key, a wrong type, an empty string and a value at each bound. Fix each difference in the schema, then delete the scratch files. [How to convert](#how-to-convert) shows a check that their types match too.
7. **Swap dependencies.** Remove `zod` and the packages that existed only for it, and add their replacements, with the project's package manager, like `pnpm remove zod` or `npm uninstall zod`. Editing `package.json` by hand leaves the lockfile stale, and some package managers then refuse to run scripts. If `arktype` is already a dependency, keep that version. Don't upgrade another dependency to a new major version, like the MCP SDK to v2, so it takes ArkType; keep Zod for it as the table says. If a dependency requires `zod` as a peer dependency, keep it installed for that dependency and say so.
8. **Verify.** Run the `typecheck` and `test` scripts in `package.json` until both pass; `npx tsc` alone can miss a second tsconfig. Run the `build` script too, if there is one. If there's no `test` script, step 6's comparison is the behavior check, so say what it covered. Search again for imports of the old library, and check that every file importing `arktype`, `.js` files included, imports the config first if it creates a Type. Change a test only where it asserts the old library itself, like a Zod error message or `instanceof ZodError`. Never delete a test, weaken an assertion or change an expected value to match new output. The exception is a snapshot of generated JSON Schema, which ArkType writes in a canonical order: required keys, then optional ones, each sorted, and enum and union members sorted. Reorder such a snapshot only when order is its only difference.
9. **Precompile, if asked.** Set it up as the skill's `references/precompile.md`, or [Precompile setup](/docs/precompile/setup), says: add `@ark/aot` and the plugin for the bundler, name the config file from step 3 as `config` in `ark.json`, run `npx arktype-precompile --check src` until it accepts every definition, then run the `typecheck`, `test` and `build` scripts again. A precompiled validator's messages don't include the value, like `(was "x")`, so a test asserting ArkType's full message text changes with them.
10. **Report** what still behaves differently, if anything, such as error message text, any snapshot you reordered, and any dependency you kept Zod for.

## How to convert

1. Write each schema as the TypeScript type it validates. Most constructs become a string or an object definition; this page's tables map them library by library.
2. Check every row of [Defaults that differ](#defaults-that-differ). A translation that looks right can still accept or return different data.
3. Confirm the types match. While the old schema still exists, a line like this fails to compile until they do:

```ts
// ---cut-start---
import { z } from "zod"
const OldUser = z.object({ name: z.string(), tags: z.array(z.string()) })
const User = type({ name: "string", tags: "string[]" })
// ---cut-end---
type Equals<a, b> =
	[a] extends [b] ?
		[b] extends [a] ?
			true
		:	false
	:	false
const outputMatches: Equals<typeof User.infer, z.output<typeof OldUser>> = true
const inputMatches: Equals<typeof User.inferIn, z.input<typeof OldUser>> = true
```

4. Run both on the same inputs, valid and invalid, and compare which they accept and what they return.

## Adopt incrementally

You don't have to convert a project at once. ArkType and Zod both implement [Standard Schema](/docs/standard-schema), so each can stand in for the other while you convert:

- **A Zod schema works inside an ArkType definition**, so convert the schemas that use it first and the shared one later:

```ts
import { z } from "zod"

// not converted yet
const Address = z.object({ street: z.string(), city: z.string() })

const User = type({ name: "string", address: Address })
```

- **An ArkType Type works wherever a library accepts Standard Schema**, like tRPC, TanStack Form, Hono's `sValidator` or react-hook-form's `standardSchemaResolver`, so call sites can switch one at a time. [Swap integrations](#migrating-a-project) has each.

A Valibot schema embeds the same way. Yup's validates asynchronously, so it can't.

## Precompile

Once your schemas are Types, [add `@ark/aot`](/docs/intro/setup#add-the-plugin) to your bundler, so each Type ships as a standalone validator with no parser. Your definitions don't change.

A definition that still embeds a Zod or Valibot schema can't be precompiled yet, so the build fails, naming it. Until you've converted it, build with `runtime: "arktype"`, which ships arktype, so what the build can't precompile runs as it did before:

```ts title="vite.config.ts"
// @noErrors
import { precompile } from "@ark/aot/unplugin"
import { defineConfig } from "vite"

export default defineConfig({
	plugins: [precompile.vite({ runtime: "arktype" })]
})
```

To see what's left, run `npx arktype-precompile --check`, which lists each definition the default build would refuse. See [Dynamic vs Precompiled](/docs/precompile/dynamic-vs-precompiled).

## Yup

Yup converts values unless `.strict()`, and treats a field as optional unless `.required()`. Translate what the data actually is: a form posting strings needs `"string.numeric.parse"` where Yup's `number()` converted. Like Joi, Yup applies a default to a key present as `undefined`, where `"key": "T = x"` rejects it; [Defaults that differ](#defaults-that-differ) has the pattern that keeps it.

| Yup                                                   | ArkType                                                                                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `object({...})`, `.shape({...})`                      | `type({...})`, `.merge({...})`                                                                                                              |
| `string()` (not required)                             | `"key?": "string \| undefined"`                                                                                                             |
| `.required()`, `.defined()`, `.nullable()`            | `"key": "string > 0"` for strings, `"key": "T"`, `"T \| null"`                                                                              |
| `.default(x)`                                         | `"key": "T = x"`                                                                                                                            |
| `.email()`, `.url()`, `.uuid()`, `.matches(r)`        | `"string.email"`, `"string.url"`, `"string.uuid"`, `/r/`                                                                                    |
| `.min(n)`, `.max(n)`, `.length(n)` on strings, arrays | `"string >= n"`, `"T[] <= n"`, `"string == n"`                                                                                              |
| `.integer()`, `.positive()`, `.moreThan(n)`           | `"number.integer"`, `"number > 0"`, `"number > n"`                                                                                          |
| `.trim()`, `.lowercase()`                             | `"string.trim"`, `"string.lower"`                                                                                                           |
| `.oneOf(["a", "b"])`                                  | `"'a' \| 'b'"`                                                                                                                              |
| `array().of(T)`, `tuple([A, B])`                      | `T.array()`, `[A, B]`                                                                                                                       |
| `.test(name, message, fn)`                            | `.narrow((x, ctx) => fn(x) \|\| ctx.reject({ message }))`                                                                                   |
| `.oneOf([ref("password")])`                           | a `.narrow()` on the object comparing the keys, which runs only once every key is valid, where Yup reports the mismatch beside other errors |
| `.transform(fn)`                                      | `.pipe(fn)`                                                                                                                                 |
| `.when("other", ...)`                                 | a union of the cases, or a `.narrow()` on the object                                                                                        |
| `lazy`                                                | a scope or `this`                                                                                                                           |
| `.noUnknown()`, `stripUnknown: true`                  | `"+": "reject"`, `"+": "delete"`                                                                                                            |
| `InferType<typeof S>`                                 | `typeof T.infer`                                                                                                                            |
| `validateSync(x)`, `isValidSync(x)`, `validate(x)`    | `T.assert(x)`, `T.allows(x)`, `T(x)`                                                                                                        |

## Joi

Joi rejects undeclared keys, rejects empty strings, and converts strings to numbers, booleans and dates unless `convert: false`. ArkType reads an ISO date-time without an offset as UTC, where Joi reads it in local time. Joi also applies a default to a key present as `undefined`; see [Defaults that differ](#defaults-that-differ). It infers no types, so `typeof T.infer` replaces the interfaces written next to Joi schemas.

| Joi                                            | ArkType                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------ |
| `Joi.object({...})`, `.unknown(true)`          | `type({ "+": "reject", ... })`, `type({...})`                                  |
| `Joi.string()` (optional), `.required()`       | `"key?": "string > 0 \| undefined"`, `"key": "string > 0"`                     |
| `.allow("")`, `.allow(null)`                   | `"string"`, `"string \| null"`                                                 |
| `.valid("a", "b")`                             | `"'a' \| 'b'"`                                                                 |
| `.email()`, `.uri()`, `.guid()`, `.pattern(r)` | `"string.email"`, `"string.url"`, `"string.uuid"`, `/r/`                       |
| `.min(n)`, `.max(n)`, `.length(n)`             | `"string >= n"`, `"string <= n"`, `"string == n"`                              |
| `Joi.number().integer().positive()`            | `"number.integer > 0"`                                                         |
| `Joi.number()` reading strings                 | `"number \| string.numeric.parse"`                                             |
| `Joi.boolean()` reading strings                | `type("boolean \| 'true' \| 'false'").pipe(v => v === true \|\| v === "true")` |
| `Joi.date()`, `Joi.date().iso()`               | `"Date \| string.date.parse"`, `"string.date.iso.parse"`                       |
| `Joi.array().items(T)`, `.min(1)`              | `T.array()`, `"T[] >= 1"`                                                      |
| `.unique()`                                    | `.narrow((a, ctx) => new Set(a).size === a.length \|\| ctx.reject("unique"))`  |
| `Joi.alternatives().try(A, B)`                 | `A.or(B)`                                                                      |
| `.default(x)`                                  | `"key": "T = x"`                                                               |
| `.custom(fn)`                                  | `.narrow()` or `.pipe()`                                                       |
| `.messages({...})`                             | `.configure({ message })`                                                      |
| `Joi.link("#id")`                              | a scope or `this`                                                              |
| `.when(...)`                                   | a union of the cases, or a `.narrow()` on the object                           |
| `schema.validate(x)`, `.attempt(x, schema)`    | `T(x)`, `T.assert(x)`                                                          |

## Effect Schema

Names are Effect 3's. Effect 4 renames some: `Schema.filter` is `Schema.check`, `Schema.transform` is `Schema.decodeTo` and `Schema.Enums` is `Schema.Enum`.

| Effect Schema                                                   | ArkType                                                              |
| --------------------------------------------------------------- | -------------------------------------------------------------------- |
| `Schema.Struct({...})`                                          | `type({ "+": "delete", ... })`                                       |
| `Schema.optional(T)`, `Schema.optionalWith(T, { exact: true })` | `"key?": "T \| undefined"`, `"key?": "T"`                            |
| `Schema.optionalWith(T, { default: () => x })`                  | `"key": "T = x"`                                                     |
| `Schema.NullOr`, `Schema.NullishOr`                             | `"T \| null"`, `"T \| null \| undefined"`                            |
| `Schema.Literal("a", "b")`, `Schema.Enums(E)`                   | `"'a' \| 'b'"`, `type.valueOf(E)`                                    |
| `Schema.Union(A, B)`, `Schema.TaggedStruct`                     | `A.or(B)`, an object with a literal `_tag`                           |
| `Schema.Array`, `Schema.NonEmptyArray`, `Schema.Tuple`          | `"T[]"`, `"T[] >= 1"`, `[A, B]`                                      |
| `Schema.Record({ key: Schema.String, value: T })`               | `"Record<string, T>"`                                                |
| `Schema.suspend(() => T)`                                       | a scope or `this`                                                    |
| `Schema.Int`, `Schema.Positive`, `Schema.between(a, b)`         | `"number.integer"`, `"number > 0"`, `"a <= number <= b"`             |
| `Schema.minLength`, `Schema.pattern(r)`, `Schema.UUID`          | `"string >= n"`, `/r/`, `"string.uuid"`                              |
| `Schema.NumberFromString`, `Schema.DateFromString`              | `"string.numeric.parse"`, `"string.date.parse"`                      |
| `Schema.Trim`, `Schema.Lowercase`, `Schema.parseJson(T)`        | `"string.trim"`, `"string.lower"`, `type("string.json.parse").to(T)` |
| `Schema.filter(fn)`                                             | `.narrow(fn)`                                                        |
| `Schema.transform(From, To, { decode, encode })`                | `codec(From, To, { decode, encode })`                                |
| `Schema.brand("Id")`                                            | `.brand("Id")`                                                       |
| `Schema.Type<typeof S>`, `Schema.Encoded<typeof S>`             | `typeof T.infer`, `typeof T.inferIn`                                 |
| `Schema.decodeUnknownSync`, `decodeUnknownEither`               | `T.assert(x)`, `T(x)`                                                |

`codec` comes from `arktype/codecs`, and importing it is what makes `.encode` available. A `Schema.Class` becomes a Type plus, if you need methods, your own class constructed from its output.

## JSON Schema and ajv

To keep a schema as JSON, convert it at runtime with `jsonSchemaToType` from `@ark/json-schema`; it accepts exactly what a JSON Schema 2020-12 validator accepts, except that lengths count UTF-16 code units, with `format` as an annotation. To rewrite it as definitions:

| JSON Schema                                              | ArkType                                                                |
| -------------------------------------------------------- | ---------------------------------------------------------------------- |
| `{ type: "string", minLength: 1, maxLength: 255 }`       | `"1 <= string <= 255"`                                                 |
| `{ type: "string", pattern: "^a" }`                      | `/^a/`                                                                 |
| `{ type: "integer", minimum: 0, exclusiveMaximum: 10 }`  | `"0 <= number.integer < 10"`                                           |
| `{ multipleOf: 5 }`                                      | `"number % 5"`                                                         |
| `{ enum: ["a", "b"] }`, `{ const: "a" }`                 | `"'a' \| 'b'"`, `"'a'"`                                                |
| `{ type: ["string", "null"] }`, `anyOf`, `oneOf`         | `"string \| null"`, `A.or(B)`                                          |
| `allOf`                                                  | `A.and(B)`                                                             |
| `properties` with `required`                             | keys, with `?` on those not required                                   |
| `additionalProperties: false`, `additionalProperties: T` | `"+": "reject"`, `"[string]": "T \| A"`, `A` the declared keys' types  |
| `patternProperties: { "^x-": T }`                        | `"[/^x-/]": T`                                                         |
| `{ type: "array", items: T, minItems: 1 }`               | `"T[] >= 1"`                                                           |
| `prefixItems`                                            | `[A, B]`                                                               |
| `$defs` with `$ref`                                      | a scope                                                                |
| `format: "email"`, `"uuid"`, `"date-time"`, `"uri"`      | `"string.email"`, `"string.uuid"`, `"string.date.iso"`, `"string.url"` |
| `default`                                                | `"key": "T = x"`                                                       |

ajv options map too: `removeAdditional` is `"+": "delete"`, `useDefaults` is a default in the definition, and `coerceTypes` is a parse keyword like `string.numeric.parse`. `T.toJsonSchema()` converts back.
