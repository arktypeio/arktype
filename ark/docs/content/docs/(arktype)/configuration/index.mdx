## Levels

Config can be set at three levels. A more specific level overrides a broader one.

### Global

Call `configure` from `"arktype/config"` in its own file, and import that file before anything else:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ numberAllowsNaN: true })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

// true
type.number.allows(Number.NaN)
```

<Callout type="warn" title="Configure before importing arktype">
	ArkType reads global config when it is first imported. Import your config file
	before any import of `"arktype"` or `"@ark/schema"`, including deep imports
	like `"arktype/internal/*"`. Config applied later reaches only scopes created
	after it, never `type` or built-in keywords. `locale` is the exception: it
	applies whenever it is configured.
</Callout>

### Scope

Pass config as the second argument to `scope` or `type.module`. It applies to every Type parsed in that scope:

```ts
const $ = scope(
	{ User: { age: "number < 100" } },
	{ max: { actual: () => "unacceptably large" } }
)

// ArkErrors: age must be less than 100 (was unacceptably large)
$.export().User({ age: 101 })

// ArkErrors: age must be at most 100 (was unacceptably large)
$.type({ age: "number <= 100" })({ age: 101 })
```

### Type

`.configure` adds [metadata](/docs/expressions#meta), like a `description` or [error parts](#errors), to a Type. It applies wherever that Type is referenced, but not to the Types inside it:

```ts
// don't print the password
const Password = type("string >= 8").configure({ actual: "" })

const User = type({
	email: "string.email",
	password: Password
})

// ArkErrors: password must be at least length 8
User({ email: "david@arktype.io", password: "ez123" })
```

## Options

| option                                                      | default                                            | levels               |
| ----------------------------------------------------------- | -------------------------------------------------- | -------------------- |
| [`onUndeclaredKey`](#onundeclaredkey)                       | `"ignore"`                                         | global, type (`"+"`) |
| [`rejectAllowsSymbolKeys`](#rejectallowssymbolkeys)         | `false`                                            | global               |
| [`exactOptionalPropertyTypes`](#exactoptionalpropertytypes) | `true`                                             | global, scope        |
| [`numberAllowsNaN`](#numberallowsnan)                       | `false`                                            | global               |
| [`numberAllowsInfinity`](#numberallowsinfinity)             | `false`                                            | global               |
| [`dateAllowsInvalid`](#dateallowsinvalid)                   | `false`                                            | global               |
| [`jitless`](#jitless)                                       | `false`, or `true` where `new Function` is blocked | global, scope        |
| [`onFail`](#onfail)                                         | `null`, which returns `ArkErrors`                  | global, scope        |
| [`keywords`](#keywords)                                     | `{}`                                               | global               |
| [`locale`](#locale)                                         | `en`                                               | global               |
| [an error code](#by-code), like `divisor`                   | ArkType's messages                                 | global, scope        |
| [`toJsonSchema`](#tojsonschema)                             | draft 2020-12, throwing for what it can't express  | global, scope        |

A Type's own options are its [metadata](/docs/expressions#meta), including the [parts of its errors](#errors).

## Errors

Each error message is built from parts. Configure the part you want to change, and ArkType keeps composing the rest, including messages for unions and intersections. `expected`, `actual`, `problem` and `message` each take a string or a function. See [Errors](/docs/errors) for what an error contains.

### description

What follows "must be" in a message. Other parts and the Type's `.description` reuse it, so it should be your first choice:

```ts
const Even = type("number % 2").describe("an even number")

// ArkErrors: must be an even number (was 3)
Even(3)
```

### expected

Like `description`, but only for error messages, where it takes precedence. A function receives the error, so it can read `code`, `data` and `path`:

```ts
const Password = type("string >= 8").configure({
	expected: ctx =>
		ctx.code === "minLength" ? `${ctx.rule} characters or more` : "a password"
})

// ArkErrors: must be 8 characters or more (was 5)
Password("ez123")

// ArkErrors: must be a password (was a number)
Password(12345678)
```

### actual

What goes inside "(was …)". An empty string omits it. A function receives the data, then the error:

```ts
const Password = type("string >= 8").configure({ actual: "" })

// ArkErrors: must be at least length 8
Password("ez123")
```

### problem

The whole sentence after the path, like "must be a string (was a number)". A function receives the error, including its `expected` and `actual`. It may not apply to the errors of a union:

```ts
const Name = type("string").configure({
	problem: ctx => `${ctx.actual} isn't ${ctx.expected}`
})

// ArkErrors: a number isn't a string
Name(5)
```

### message

The whole message, including the path. A function receives the error, including its `problem`. It may not apply to the errors of a union:

```ts
const User = type({
	password: "string >= 8"
}).configure({
	message: ctx => `${ctx.propString || "(root)"}: ${ctx.problem}`
})

// ArkErrors: (root): must be an object (was a string)
User("ez123")

// .configure applies only at the root, so the nested error is unchanged
// ArkErrors: password must be at least length 8 (was 5)
User({ password: "ez123" })
```

Each function also receives the active [locale](/docs/i18n#your-own-messages) as its last argument, so it can write its text in the language a message is read in.

### By code

Globally or in a scope, configure errors by their [code](/docs/errors#error-codes). A function's `ctx` is typed by its code:

```ts
const mod = type.module(
	{ isEven: "number % 2" },
	{
		divisor: {
			expected: ctx => `% ${ctx.rule} !== 0`,
			problem: ctx => `${ctx.actual} ${ctx.expected}`
		}
	}
)

// ArkErrors: 3 % 2 !== 0
mod.isEven(3)
```

A key that `"+": "reject"` disallows has the code `undeclared`:

```ts
const $ = scope(
	{ User: { "+": "reject", name: "string" } },
	{ undeclared: { problem: "isn't allowed" } }
)

// ArkErrors: age isn't allowed
$.export().User({ name: "Alice", age: 42 })
```

Each kind of constraint, like `domain` or `divisor`, also takes a `description` function. It receives the constraint and changes how it is described everywhere, not only in errors.

## locale

Error messages are written in English by default. Configure a locale to write them in another language:

```ts title="config.ts"
import { configure } from "arktype/config"
import { de } from "arktype/locales/de"

configure({ locale: de })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

// ArkErrors: muss eine Zeichenkette sein, ist aber eine Zahl
type.string(5)
```

`locale` can also be a function that returns a locale each time a message is read. See [i18n](/docs/i18n).

## keywords

Configure built-in keywords like `string.email` by name. Each takes a description or the same options as [`.configure`](#type):

```ts title="config.ts"
import { configure } from "arktype/config"

configure({
	keywords: {
		string: "text",
		"string.email": {
			actual: () => "definitely fake"
		}
	}
})
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

const User = type({
	name: "string",
	email: "string.email"
})

// ArkErrors: email must be an email address (was definitely fake)
//            name must be text (was a number)
User({ name: 5, email: "449 Canal St" })
```

## onUndeclaredKey

Like TypeScript, ArkType ignores keys an object doesn't declare by default. There are three behaviors:

- `"ignore"` (default): allow undeclared keys and keep them in the output
- `"delete"`: allow undeclared keys and remove them from the output
- `"reject"`: fail on undeclared keys

Set it for one object with [`"+"`](/docs/objects#properties-undeclared), or change the default globally:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ onUndeclaredKey: "delete" })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

const UserForm = type({
	name: "string"
})

// { name: "Alice" }
UserForm({ name: "Alice", age: "42" })
```

## rejectAllowsSymbolKeys

`"reject"` checks symbol keys too, which costs an extra read per object. If you don't need undeclared symbol keys rejected, allow them:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ rejectAllowsSymbolKeys: true })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

const User = type({
	"+": "reject",
	name: "string"
})

// valid, since undeclared symbol keys are allowed
User({ name: "Alice", [Symbol("id")]: 1 })
```

With it, two `"+": "reject"` objects that differ only by a symbol key accept the same values, so a union of them that includes a morph throws a `ParseError`.

## exactOptionalPropertyTypes

By default, ArkType treats optional keys as TypeScript does with [`exactOptionalPropertyTypes`](https://www.typescriptlang.org/tsconfig/#exactOptionalPropertyTypes): an optional key can be omitted, but not set to `undefined`.

```ts
const MyObj = type({
	"key?": "number"
})

// {}
MyObj({})

// ArkErrors: key must be a number (was undefined)
MyObj({ key: undefined })
```

Add `| undefined` to keys that should accept it. If your tsconfig doesn't enable `exactOptionalPropertyTypes`, you can set ArkType's to `false` to match:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ exactOptionalPropertyTypes: false })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

const MyObj = type({
	"key?": "number",
	withDefault: "number = 5"
})

// { key: undefined, withDefault: undefined }
MyObj({ key: undefined, withDefault: undefined })
```

With `false`, an explicit `undefined` also passes for a key with a default, and is kept rather than replaced by the default. Configurable defaults are tracked in [#1390](https://github.com/arktypeio/arktype/issues/1390).

## numberAllowsNaN

`number` rejects `NaN` by default. Allow it everywhere with `numberAllowsNaN: true`, or in one Type with the `number.NaN` keyword:

```ts
const MaybeNaN = type("number | number.NaN")

// NaN
MaybeNaN(Number.NaN)
```

## numberAllowsInfinity

`number` rejects `Infinity` and `-Infinity` by default. Allow them everywhere with `numberAllowsInfinity: true`, or in one Type with the `number.Infinity` and `number.NegativeInfinity` keywords:

```ts
const Limit = type("number | number.Infinity")

// ArkErrors: must be a number (was Infinity)
type.number(Infinity)

// Infinity
Limit(Infinity)
```

## dateAllowsInvalid

`Date` rejects an invalid date, like `new Date("x")`, by default. Allow it with `dateAllowsInvalid: true`:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ dateAllowsInvalid: true })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

// Invalid Date
type("Date")(new Date("x"))
```

## jitless

ArkType compiles each Type to optimized validation code using `new Function`. Where that's blocked, like Cloudflare Workers, it validates without compiling instead. To turn compiling off yourself, set `jitless: true`:

```ts title="config.ts"
import { configure } from "arktype/config"

configure({ jitless: true })
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

// will not be compiled
const MyObject = type({
	foo: "string"
})
```

Configuring `jitless` globally also skips the check for `new Function`, which a strict Content-Security-Policy would report as a violation.

## onFail

To throw on every failed validation, or transform its result some other way, configure `onFail`. Declare its return type on `ArkEnv` so calls are typed to match:

```ts title="config.ts"
import { configure } from "arktype/config"

const config = configure({
	onFail: errors => errors.throw()
})

declare global {
	interface ArkEnv {
		onFail: typeof config.onFail
	}
}
```

```ts title="app.ts"
import "./config.ts"
// import your config file before arktype
import { type } from "arktype"

// string, since a failure throws instead of returning ArkErrors
const data = type.string("foo")

// TraversalError: must be a string (was a number)
type.string(5)
```

`onFail` can also be passed to a scope.

## toJsonSchema

`toJsonSchema` sets the defaults for `.toJsonSchema()`, like its target and how to handle what JSON Schema can't express. See [JSON Schema](/docs/json-schema/to-json-schema).

## metadata

<AnchorAliases custom />

Add your own keys to the metadata Types accept by extending `ArkEnv`:

```ts
// add this anywhere in your project
declare global {
	interface ArkEnv {
		meta(): {
			// meta properties should always be optional
			secretIngredient?: string
		}
	}
}

// now types you define can specify and access your metadata
const MrPingsSecretIngredientSoup = type({
	broth: "'miso' | 'vegetable'",
	ingredients: "string[]"
}).configure({ secretIngredient: "nothing!" })
```

## prototypes

When you `.infer` a Type, ArkType walks its inferred type to extract special values like morphs, e.g. `(In: string) => Out<number>`. For some classes that walk is slow or expands the type. Declare them in `prototypes` to have them treated as opaque:

```ts
declare global {
	interface ArkEnv {
		prototypes(): MySpecialClass
	}
}

class MySpecialClass {}

// Type<MySpecialClass>
const T = type.instanceOf(MySpecialClass)
```
