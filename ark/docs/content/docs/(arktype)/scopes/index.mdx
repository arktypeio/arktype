<AnchorAliases intro />

A scope is a set of named definitions, called aliases, that can reference each other the same way they reference keywords like `string`. The `type` function you import from `arktype` is a method of ArkType's default scope.

## Defining a scope

Pass `scope` an object mapping alias names to definitions:

```ts
import { scope } from "arktype"

const $ = scope({
	Id: "string",
	User: { id: "Id", friends: "Id[]" },
	UsersById: { "[Id]": "User" }
})
```

Aliases are autocompleted and validated like built-in keywords. Write definitions inside a scope directly: wrapping one in `type(...)` fails, because `type` only knows built-in keywords (see [thunks](#thunks)).

`$.type` parses a definition that can reference the scope's aliases. Types created this way keep their scope, so chained methods can reference the aliases too:

```ts
const $ = scope({
	Id: "string",
	User: { id: "Id", friends: "Id[]" },
	UsersById: { "[Id]": "User" }
})
// ---cut---
const Group = $.type({ name: "string", members: "User[]" })

const OwnedGroup = Group.and({ ownerId: "Id" })
```

`$.match`, `$.declare`, `$.generic` and `$.fn` work like their counterparts on `type`, but also resolve the scope's aliases.

## Modules

`.export()` turns a scope into a `Module`, an object mapping each alias to its `Type`:

```ts
const $ = scope({
	Id: "string",
	User: { id: "Id", friends: "Id[]" },
	UsersById: { "[Id]": "User" }
})
// ---cut---
const types = $.export()

// ArkErrors: friends[1] must be a string (was a number)
types.User({ id: "99", friends: ["7", 8, "9"] })
```

To get a single `Type`, use `$.resolve("User")`.

`type.module` defines a scope and exports it in one call:

```ts
const types = type.module({
	Id: "string",
	User: { id: "Id", friends: "Id[]" }
})
```

A `Module` can be spread into another scope to include all of its aliases. Pass names to `.export()` to include only those:

```ts
const $ = scope({
	Id: "string",
	User: { id: "Id", friends: "Id[]" },
	UsersById: { "[Id]": "User" }
})
// ---cut---
const numbers = scope({ Three: "3", Sixty: "60", No: "'no'" })

const superScope = scope({
	...$.export(),
	...numbers.export("Three", "Sixty"),
	Saiyan: { powerLevel: "number > 9000" }
})
```

## Cyclic types

Aliases can reference themselves and each other:

```ts
const types = scope({
	Package: {
		name: "string",
		"dependencies?": "Package[]",
		"contributors?": "Contributor[]"
	},
	Contributor: {
		email: "string.email",
		"packages?": "Package[]"
	}
}).export()
```

Cyclic types are inferred to any depth, and they validate cyclic data:

```ts
const types = scope({
	Package: {
		name: "string",
		"dependencies?": "Package[]",
		"contributors?": "Contributor[]"
	},
	Contributor: {
		email: "string.email",
		"packages?": "Package[]"
	}
}).export()
// ---cut---
type Package = typeof types.Package.infer

const packageData: Package = {
	name: "arktype",
	dependencies: [{ name: "typescript" }],
	contributors: [{ email: "david@sharktypeio" }]
}

// arktype now depends on itself
packageData.dependencies![0].dependencies = [packageData]

// ArkErrors: contributors[0].email must be an email address (was "david@sharktypeio")
types.Package(packageData)
```

A cycle must pass through an object, array or morph. An alias that resolves to itself without one, like `a` in `scope({ a: "a | string" })`, is a type error and throws a `ParseError`.

For a single recursive `Type`, you don't need a scope: use the [`this`](/docs/expressions#this) keyword.

<Callout type="warn" title="Cyclic types may display as any">

TypeScript shows an anonymous cycle as `...`, or as `any` if `noErrorTruncation` is enabled. Either way, the type itself is accurate: you get completions, and accessing a property that doesn't exist is an error.

</Callout>

## Visibility

Aliases prefixed with `#` are private. They can be referenced in the scope, but are not exported:

```ts
const shapes = scope({
	"#BaseShape": { perimeter: "number", area: "number" },
	// reference private aliases without the "#"
	Ellipse: { "...": "BaseShape", radii: ["number", "number"] },
	Rectangle: { "...": "BaseShape", width: "number", height: "number" }
})

// shapes.type can still reference private aliases
const PartialShape = shapes.type("Partial<BaseShape>")

const shapeModule = shapes.export()
Object.keys(shapeModule) // ["Ellipse", "Rectangle"]
```

### `import()`

`.import()` is like `.export()`, but makes every alias private. Spread it into a scope to use another scope's aliases without re-exporting them:

```ts
const utilities = scope({
	"WithId<o extends object>": { "...": "o", id: "string" }
})

const userModule = type.module({
	...utilities.import(),
	Payload: { name: "string", age: "number" },
	Db: "WithId<Payload>"
})

Object.keys(userModule) // ["Payload", "Db"]
```

## Submodules

Keywords like `string.email` are grouped into submodules. To group your own aliases, assign a `Module` to an alias and reference its members with a `.`:

```ts
const ids = type.module({ User: "string", Order: "number" })

const $ = scope({
	Id: ids,
	Customer: { id: "Id.User", orderIds: "Id.Order[]" }
})
```

Submodules are parsed bottom-up: the root scope can reference a submodule's aliases, but a submodule can't reference the root scope's aliases.

### Nested

Submodules can be nested to any depth:

```ts
const ids = type.module({ User: "string", Order: "number" })

const $ = scope({
	Id: ids,
	Customer: { id: "Id.User", orderIds: "Id.Order[]" }
})
// ---cut---
const store = scope({ Store: $.export() })

const OrderIds = store.type("Store.Id.Order[]")
```

### Rooted

A submodule can't be referenced as a `Type` itself unless it has an alias named `root`, the way `string` is both a keyword and the prefix of `string.email`:

```ts
const userModule = type.module({
	root: { name: "string" },
	// subaliases can reference root like any other alias
	Admin: { "...": "root", isAdmin: "true" },
	Saiyan: { "...": "root", powerLevel: "number > 9000" }
})

const types = type.module({
	User: userModule,
	// User refers to the root alias
	Group: "User[]",
	// or prefixes its subaliases
	ElevatedUser: "User.Admin | User.Saiyan"
})
```

## Thunks

A common mistake is wrapping a scoped definition in `type`:

```ts
// @errors: 2322
const $ = scope({
	Id: "string",
	User: type({
		name: "string",
		id: "Id"
	})
})
```

`Id` exists in the scope, but `type` only knows built-in keywords. Here the wrapper is redundant, so remove it:

```ts
const $ = scope({
	Id: "string",
	User: {
		name: "string",
		id: "Id"
	}
})
```

To use fluent methods like `.pipe` on a scoped definition, define it as a thunk: a function that calls the `type` method of the scope you're defining.

```ts
const $ = scope({
	Id: "string",
	TrimmedId: () => $.type("Id").pipe(s => s.trim())
})

const types = $.export()

types.TrimmedId("  42 ") // "42"
```

A thunk can't pass a callback that receives the data, like `.narrow`'s, to a Type that references the alias the thunk defines. TypeScript would read the callback's parameter from that alias, which is still being inferred from the thunk, and reports the thunk as implicitly `any`. Write the narrow as a tuple expression instead:

```ts
const $ = scope({
	File: { name: "string" },
	Directory: {
		name: "string",
		children: [
			"(File | Directory)[]",
			":",
			children => new Set(children.map(c => c.name)).size === children.length
		]
	}
})
```

## Configuration

`scope` takes a config as its second argument. It applies to every `Type` parsed in the scope:

```ts
const $ = scope({ Even: "number % 2" }, { divisor: { expected: "even" } })

// ArkErrors: must be even (was 3)
$.export().Even(3)
```

It accepts the same options as [global configuration](/docs/configuration), except these, which can only be configured globally: `onUndeclaredKey`, `numberAllowsNaN`, `numberAllowsInfinity`, `dateAllowsInvalid`, `keywords` and `locale`.
