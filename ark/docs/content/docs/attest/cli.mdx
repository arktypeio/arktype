---
title: CLI
description: Summarize, trace and precache your project's type performance from the attest command.
---

`@ark/attest` installs an `attest` command, which you can run with `npx attest` or from a `package.json` script. `stats` and `trace` run `tsc` through `npm exec`, and both work for projects with `composite: true`.

## stats

```bash
npx attest stats packages/*
```

Type-checks each directory you pass with its own tsconfig, then prints its check time, type count and instantiation count, and the totals across all of them. With no arguments, it checks the current directory.

attest doesn't expand globs itself, so `packages/*` relies on your shell. Shells like Windows `cmd` don't expand it.

## trace

```bash
npx attest trace
```

Runs `tsc --generateTrace` on the `tsconfig.json` in the current directory and writes the results to `.attest/trace`:

- `trace.json`, which you can open in [Perfetto](https://ui.perfetto.dev/) as a type performance heat map
- `summary.txt`, with the slowest individual calls and the functions ranked by self time, which it also prints
- `ranges.csv` and `names.csv`, the same data per call and per function name

It has to run from a directory with a `tsconfig.json`. An optional argument sets the directory `tsc` runs in, which defaults to the current one.

## precache

```bash
npx attest precache
```

Writes the type data `setup` would, to `.attest/assertions.json` or the path you pass. Assertions read it from `.attest/assertions.json`, but `setup` deletes and rewrites that file, so a precached file is only used by tests that run without `setup`, e.g. CI jobs that share the output of one type-checking step.
