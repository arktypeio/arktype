---
title: Custom assertions
description: Read the type data attest collects from your own assertion functions.
---

If you're a library author who wants type data in your own assertions rather than through `attest`, tell `setup` which function names to analyze with `attestAliases`.

## Setup

```ts
import { setup } from "@ark/attest"

// replaces the default ["attest", "attestInternal"], so keep "attest" if you use it
setup({ attestAliases: ["attest", "yourCustomAssert"] })
```

`setup` has to run with these aliases before the first test. It finds every call to them in your project and writes their types to `.attest/assertions.json`, so assertions in any test process can read them without starting TypeScript.

## Type data

<AnchorAliases apis />

`caller` returns the position your function was called from, and `getTypeAssertionAtPosition` returns the data `setup` recorded for the call there:

```ts
import { caller, getTypeAssertionAtPosition } from "@ark/attest"

export const yourCustomAssert = <expectedType>(actualValue: expectedType) => {
	const assertion = getTypeAssertionAtPosition(caller())
	const actual = assertion.args[0]
	// how the value's type relates to the expected type argument
	const relationship = actual.relationships.typeArgs[0]
	if (relationship === undefined) {
		throw new Error(
			`yourCustomAssert requires an expected type, e.g. yourCustomAssert<"foo">("foo")`
		)
	}
	if (relationship !== "equality") {
		throw new Error(
			`Expected ${assertion.typeArgs[0].type}, got ${actual.type} with relationship ${relationship}`
		)
	}
}
```

A user might then call it like this:

```ts
// @filename: your-package.d.ts
declare module "your-package" {
	export const yourCustomAssert: <expectedType>(
		actualValue: expectedType
	) => void
}
// @filename: index.ts
// ---cut---
import { yourCustomAssert } from "your-package"

// passes
yourCustomAssert<"foo">(`${"f"}oo` as const)
// throws "Expected boolean, got true with relationship subtype"
yourCustomAssert<boolean>(true)
// throws "Expected 5, got number with relationship supertype"
// @ts-expect-error
yourCustomAssert<5>(2 + 3)
```

The data for each call (`TypeAssertionData`) has:

- `args` and `typeArgs`: for each argument and type argument, its `type` as TypeScript displays it, and `relationships.args` and `relationships.typeArgs`, how it relates to each argument and type argument: `"subtype"`, `"supertype"`, `"equality"` or `"none"`
- `errors`: the messages of the type errors reported for the call
- `completions`: the completions of each string literal in the first argument
- `jsdoc`: the JSDoc of the first argument, if any
- `location`: the call's start and end `{ line, char }`

If your assertion is called through a helper of yours, `caller()` returns the position of the call in the helper. Pass `caller({ upStackBy: 4 })` to look one call further up the stack, or a `skip` function that returns `true` for each position to move past, e.g. `caller({ skip: position => position.method === "yourHelper" })`.

## Instantiations

A call to `.instantiations` on an alias, e.g. `yourCustomAssert.instantiations()`, records the instantiations contributed by the test it's in. `getBenchAssertionAtPosition` returns that count:

```ts
declare const yourCustomAssert: { instantiations: (max: number) => void }
// ---cut---
import { caller, getBenchAssertionAtPosition } from "@ark/attest"

yourCustomAssert.instantiations = (max: number) => {
	const { count } = getBenchAssertionAtPosition(caller())
	if (count > max) throw new Error(`${count} instantiations exceeds ${max}`)
}
```

## Without setup

`writeAssertionData(path)` type-checks your project and writes the type data to `path`, as `setup` does without deleting `.attest` or recording config. Assertions read it from `.attest/assertions.json`.
