---
title: Options
description: Every attest option, its default, and how to set it from setup, a flag or an environment variable.
---

Set an option in one of three ways:

- Pass it to `setup`, e.g. `setup({ skipTypes: true })`.
- Pass it as a flag to the process that runs your tests or benches, e.g. `--skipTypes` or `--benchPercentThreshold 10`. A boolean option is turned on by its flag alone.
- Set it as an environment variable prefixed with `ATTEST_`, e.g. `ATTEST_skipTypes=true` or `ATTEST_benchPercentThreshold=10`. Values are parsed as JSON, so a string needs quotes: `ATTEST_filter='"keyword"'`.

Flags and options passed to `setup` both override environment variables. Avoid setting an option both in `setup` and as a flag: `setup` uses its own value, but your tests use the flag's. Benches don't call `setup`, so they read only flags and environment variables.

## Options

| Option                          | Default                             | Effect                                                                                                                                                               |
| ------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skipTypes`                     | `false`                             | Skip type-checking in `setup` and every type assertion. See [below](#skiptypes).                                                                                     |
| `onlyNamedTestFiles`            | `false`                             | Type-check only the test files named on the command line. See [below](#onlynamedtestfiles).                                                                          |
| `checker`                       | see [below](#checker)               | The type checker to analyze with: `"tsjs"`, `"tsgo"` or `"tsrs"`.                                                                                                    |
| `updateSnapshots`               | `false`                             | Rewrite every snapshot and bench baseline with the current value. Also `-u` or `--update`.                                                                           |
| `failOnMissingSnapshots`        | `true` if `CI` is set               | Throw on a `.snap()` with no value rather than populating it.                                                                                                        |
| `tsconfig`                      | nearest `tsconfig.json`             | Path of the tsconfig to analyze. By default, attest looks in the working directory, then its parents. `null` ignores tsconfig files and uses only `compilerOptions`. |
| `compilerOptions`               | `{}`                                | Compiler options, as written in a tsconfig, merged over the tsconfig's. As a flag, pass JSON.                                                                        |
| `attestAliases`                 | `["attest", "attestInternal"]`      | Names of the functions whose calls `setup` analyzes. Replaces the default. As a flag, separate names with commas. See [Custom assertions](/docs/attest/integration). |
| `skipInlineInstantiations`      | `false`                             | Skip measuring and checking [`attest.instantiations`](/docs/attest/assertions#instantiations).                                                                       |
| `testDeclarationAliases`        | `["bench", "it", "test"]`           | Names of the calls whose blocks count as a bench or test when counting instantiations.                                                                               |
| `benchPercentThreshold`         | `20`                                | How far a result can exceed its baseline, in percent, before it fails. See [Thresholds](/docs/attest/benches#thresholds).                                            |
| `benchErrorOnThresholdExceeded` | `true`                              | Which results over the threshold fail: `true` (all), `false`, `"types"` or `"runtime"`.                                                                              |
| `filter`                        | none                                | Run only the bench with this name.                                                                                                                                   |
| `formatCmd`                     | `npm exec --no -- prettier --write` | Command run on each file attest writes snapshots into.                                                                                                               |
| `shouldFormat`                  | `true`                              | Whether to run `formatCmd`.                                                                                                                                          |
| `typeToStringFormat`            | `{}`                                | Prettier options for type strings. See [below](#typetostringformat).                                                                                                 |

`getDefaultAttestConfig()` returns the defaults, and the `AttestConfig` type describes what `setup` accepts. `setup` analyzes only files under the working directory.

### skipTypes

`skipTypes` makes `setup` skip type-checking your project and skips every assertion that needs type information. Use it to iterate quickly when you're only changing runtime code.

You likely want two scripts:

```json title="package.json"
"test": "ATTEST_skipTypes=true vitest run",
"testWithTypes": "vitest run"
```

Use `test` when:

- You're only changing runtime logic
- You're running tests in watch mode or from your editor's test explorer

Use `testWithTypes` when:

- You've changed types and want to recheck your type-level assertions
- You're running tests in CI

### onlyNamedTestFiles

With `onlyNamedTestFiles`, `setup` type-checks only the test files named on the command line, e.g. `vitest run src/user.test.ts`. One file checks in seconds where a large project takes minutes. With no test file named, it checks every file as before.

A named file has to be a path to a file that exists, ends in `.test.ts` (or `.test.js`, `.test.mts`, `.test.tsx` and the like), and is part of your tsconfig. A test in a file that wasn't checked fails with "Found no assertion data", so a missed file can't pass silently.

Your runner must also run only the named files. Mocha runs files named on the command line in addition to the `spec` in its config, so leave the config out (`--no-package` if it's in `package.json`) and pass the options you need as flags. Vitest rejects flags it doesn't know, so set the environment variable instead:

```bash
ATTEST_onlyNamedTestFiles=true vitest run src/user.test.ts
```

### checker

The type checker attest analyzes type assertions with:

- `"tsjs"`: TypeScript's JS API, for TypeScript 6 and earlier
- `"tsgo"`: TypeScript 7's native compiler
- `"tsrs"`: [tsrs](https://github.com/oxc-project/tsrs), a faster Rust port of TypeScript 7 that serves the same API

By default, attest uses tsrs if it's installed alongside TypeScript 7 on a platform it ships a binary for, otherwise the checker matching your TypeScript version. Setting a checker that doesn't match your installed TypeScript throws.

### typeToStringFormat

[Prettier options](https://prettier.io/docs/en/options.html) for the type strings of `.type.toString` and `.jsdoc`. Yours override these defaults:

```json
{
	"semi": false,
	// note this print width is optimized for type serialization, not general code
	"printWidth": 60,
	"trailingComma": "none",
	"parser": "typescript"
}
```

As a flag or environment variable, pass them as JSON, e.g. `--typeToStringFormat '{ "useTabs": true }'`.
