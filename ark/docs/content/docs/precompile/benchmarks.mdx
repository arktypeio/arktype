Every number on this site comes from a benchmark in the repo. This page has the rule the homepage's board follows, every result behind it, our own benchmark beside it and the commands that rerun each one.

## The board

The homepage's board has three graphs: validation speed, startup and bundle size. All three follow one rule.

1. **The results are other projects' benchmarks.** None of the benchmarks a graph averages was designed by us. Each is another project's public suite, cloned at a pinned commit and run as its authors wrote it, with ArkType added the way that suite adds a library. The one exception is in size: valibot.dev's login form is Valibot's code, which we wrote in each other library and size with our own script.
2. **Each graph averages the largest set of results that five libraries share.** A graph has five lanes: ArkType, Zod and three more libraries the site names. A library is only compared over results it ran, so the graph takes the largest set of results that ArkType, Zod and three such libraries all ran. Which results those are depends on who ran what and never on what anyone scored.
3. **Every library that ran all of those results is ranked**, whether the site names it or not, by the geometric mean of its results.
4. **The lanes drawn** are ArkType, the three best-placed other libraries the site names (100k+ npm downloads a week) and Zod. Zod's other entry points, `z.compile` and Zod Mini, are in the tables below rather than in a second Zod lane.

Each choice has a reason:

- **The unit is the one the benchmark measures.** Speed and startup are CPU instructions, counted with `perf` while the other project's benchmark code runs. An instruction count is the same on a busy machine and on a quiet one, and close to the same on another CPU, so a number here can be checked on a machine that isn't ours. Size is bytes, minified and gzipped.
- **A geometric mean** because the results span orders of magnitude: one validates an email address, another a whole document. An arithmetic mean would be the largest result with the rest as rounding error. A geometric mean gives every result the same weight, and the ratio of two libraries' means is the mean of their ratios.
- **The same rows for every library** because a library that skipped the hardest results would otherwise average an easier set.
- **Startup counts creating a schema**, because that is what both public startup benchmarks time. A precompiled validator creates its schema when it builds and has nothing left to create when it loads; the graph shows that difference as it was measured. Importing a real app through its first validation is [our own startup benchmark](#startup).
- **One build of ArkType** is in every row of all three graphs: precompiled with the default options, bundled as a production build.

## Precompiled against dynamic

A precompiled validator has to return what dynamic ArkType returns, with the same messages. These are the checks every change to the precompiler passes:

| Check                   | What it holds                                                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm testDifferential` | Every Type ArkType's own test suites call, precompiled in each layout, returns what dynamic ArkType returns on every input the suites passed it.                    |
| `pnpm testPerturbation` | Change what the build read before the program runs, like a key, an export or a prototype: the precompiled program throws as it starts or still agrees with ArkType. |
| `pnpm testPrograms`     | Generated programs agree run as written and precompiled, unchanged and under every perturbation.                                                                    |
| `pnpm testPruneParity`  | A production bundle missing what no code reads validates every input as one built whole does, once negative controls show the check catches a dropped check.        |
| `pnpm testHistory`      | Each test sees the same thing fresh, twice in one process and after a random sample of the others.                                                                  |
| `pnpm testEnvironments` | A program prints the same in other time zones and locales, on Bun, Deno, Chromium and Firefox.                                                                      |

In your own project, [shadow mode](/docs/precompile/advanced#shadow-mode) runs your tests against both and fails wherever they disagree.

## Rerun them

Clone the repo and build it once:

```sh
git clone https://github.com/arktypeio/arktype
cd arktype
pnpm i && pnpm build
```

### The board

`pnpm benchExternal <suite>` clones a benchmark at the commit its published rows were counted on, installs it from its own lockfile, adds ArkType and runs it. The clones take about 4.5 GB under `ark/repo/bench/external/out/clones/`.

| Graph            | Command                                               | Needs                    | Takes            |
| ---------------- | ----------------------------------------------------- | ------------------------ | ---------------- |
| Validation speed | `pnpm benchExternal sb` and `pnpm benchExternal ata`  | Linux, `perf`, `taskset` | about 75 minutes |
| Startup          | `pnpm benchExternal sb` and `pnpm benchExternal sury` | Linux, `perf`, `taskset` | about 50 minutes |
| Bundle size      | `pnpm benchExternal size`                             | any OS                   | about 2 minutes  |
| All of them      | `pnpm benchExternal all`                              | Linux, `perf`, `taskset` | about 90 minutes |

Instruction counts come from hardware counters, which `perf` reads on Linux and which most hosted CI runners and virtual machines don't expose. `NODE24` and `NODE26` name the Node 24 and 26 binaries the suites run on; without them the suites run on the Node that runs the script.

Each run writes its results to `ark/repo/bench/external/out/fresh/`. Then:

```sh
pnpm benchBoard --fresh
```

prints each graph's standings by the rule above, the published numbers beside what your checkout measured. Without `--fresh` it prints the published ones alone. It runs the code this site runs, so what it prints for the published results is what the homepage draws.

Expect every other library's bundle to match to the byte, and an instruction count to move by a few percent on another CPU or Node build while the ratios between libraries move less. ArkType's own rows are the commit you check out, and the published ones name theirs.

### Our own benchmark

| Script                       | What it reruns                                          | Needs                    | Takes            |
| ---------------------------- | ------------------------------------------------------- | ------------------------ | ---------------- |
| `pnpm benchTypia`            | Typia's generated validators, which the next three read | any OS                   | 1 to 5 minutes   |
| `pnpm benchValidate`         | [Validation speed](#validation-speed), every scenario   | any OS                   | about 10 minutes |
| `pnpm benchImport`           | [Startup](#startup) by the clock                        | any OS                   | under a minute   |
| `pnpm benchSize`             | [Bundle size](#bundle-size) of our apps                 | any OS                   | seconds          |
| `pnpm benchExternal startup` | [Startup](#startup) in instructions                     | Linux, `perf`, `taskset` | about a minute   |

`benchValidate`, `benchImport` and `benchSize` write `validate.json`, `import.json` and `size.json` to `ark/repo/bench/out/`, and `pnpm benchBoard --fresh` prints them beside the published tables above. Times by the clock are your machine's: compare the ratios between libraries, not the nanoseconds.

`pnpm benchSizeScale` reruns [Size at scale](/docs/precompile/size-at-scale), `pnpm benchBigApp` the generated apps and ntwine, and `pnpm benchBuildTime` [Build time](/docs/precompile#build-time).

The [benchmarks' README](https://github.com/arktypeio/arktype/blob/main/ark/repo/bench/external/README.md) has what each suite needs installed, how each library was added to it, the versions every row was measured at and every run's results.
