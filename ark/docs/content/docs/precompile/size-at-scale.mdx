title: Size at scale
description: What each Type adds to a bundle, dynamic and precompiled, and where each is the smaller.

A bundle pays for validation twice: once for the library, and again for each Type. ArkType's two modes split that differently.

- **Dynamic** arktype ships its parser and compiler, a fixed cost, and each Type adds only its definition.
- **Precompiled**, neither ships, so the fixed cost is small, and each Type adds its validator: checks compiled for it by default, or with [`preset: "smallest"`](/docs/precompile/options#choosing-smallest), what shared checkers read.

So which is smaller depends on how many Types a bundle holds, and on what they hold. This page measures both, with Valibot and Zod beside them, from <SizeScaleText id="range" />.

## What's measured

<SizeScaleText id="method" /> A library whose schemas have no methods, like
Valibot or Zod Mini, is bundled with the functions that validate with them.

Each app is written twice:

- **Models** are objects of ids, bounded strings, formats, integers, enums, optional keys, defaults, arrays, references to each other and discriminated unions, as an API's requests and responses are. None has a message or a function of its own.
- **Forms** are the same Types, where <SizeScaleText id="formsRates" />. Those are the rates we counted in a production frontend's forms.

```ts
import { type } from "arktype"

const isTrimmed = (s: string) => s === s.trim()

const Contact = type({
	// a message of its own
	email: type("string.email").configure({ message: "Enter your work email." }),
	// a narrow, with its message
	name: type("1 <= string <= 100").narrow(
		(value, ctx) =>
			isTrimmed(value) ||
			ctx.reject({ message: "Name can't start or end with a space." })
	)
})
```

The default build here is the compiled one a server gets. Building for a browser, it [writes its validators for size](/docs/precompile/options#choosing-smallest) once they'd outweigh arktype.

## Which to choose

Precompile a bundle a browser loads, with [`"smallest"`](/docs/precompile/options#choosing-smallest) once it holds more than a handful of Types. <SizeScaleText id="smallestUntil" /> What it saves is arktype's fixed cost, which a page pays before it validates anything.

<SizeScaleParagraph id="outgrown" />

Keep the default build for a server and for validation on a hot path, where each validator's own compiled code is [what makes it fast](/docs/precompile#speed-and-size). <SizeScaleText id="defaultUntil" /> A bundle with both kinds of Type [chooses for each definition](/docs/precompile/options#strategies-and-schemas).

What a Type holds moves these counts more than how many there are. <SizeScaleText id="costRatios" /> If bytes are all you're choosing by, compare the rows nearest your app above.

[Dynamic vs Precompiled](/docs/precompile/dynamic-vs-precompiled#which-to-use) covers when to stay dynamic for reasons other than size.
