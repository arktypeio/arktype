# @ark/aot

## 0.0.1

Initial release: constructs arktype definitions at build time, so arktype's parser never ships (#810). It runs as a bundler plugin, as Node, Bun and Turbopack drivers, as `arktype-precompile --check`, as `arktype-precompile --emit` over what `tsc` emits and as an ESLint rule, and `arktype-precompile --declare` emits declarations sharing one file of shapes. See the [README](./README.md).

With `optimize: "size"`, as the `"smallest"` preset sets, and detailed errors, a build writes each node as a call to a small runtime checker that describes what it checks from its rule, and each site creates its validator in place. A module whose Types are too few to pay for the checkers' runtime is compiled instead.

A production webpack or Rspack build, Next.js's webpack compilers among them, writes the same validators as an esbuild build: it builds its modules as they are, reads them, so it reads what its resolver, loaders and generated entries make of them, then builds again those it writes. A build it can't read builds each module on its own, with a warning.

`next build` with Turbopack reads its project before it writes a module, as Turbopack's loader sees one module at a time and can serve only what's on disk: export next.config through `withPrecompile` from `@ark/aot/turbopack`. Each process of its pool answers from one read, its validators held once in files under `node_modules/.bin/.ark`, so a route's first load and its server output no longer grow with what each module would hold of its own. Each module is checked in each layer against what the read saw, and fails where it differs. It reads as `withPrecompile` has Next load `next.config`, before Turbopack starts, writing only what changed, so Turbopack's build cache keeps from an earlier build only what the read left as it was. It reads each route, under app/build/ or app/.well-known/ too, every script under pages/ and what a link leads to, as Next routes them. Where the project can't be read, it warns, and each module holds its own validators. Turbopack aliases `@ark/schema/runtime` to `@ark/aot/turbopack/runtime`, which the loader writes as the copy of @ark/schema's runtime the build's options load, so the aliases stay alike as the options change: Next 16.4.1 hangs a cached build past an alias removed since.

A build keeps each answer it can reuse in `node_modules/.cache/ark` where it runs, so a later build, dev server or Next process reads it while nothing that decided it changed: the module, each file the precompiler read and what each import resolved to, the options, and the precompiler's own code and Node. A watch build keeps its precompiler across changes, analyzing again only the modules a change reaches, and stores only what it answered before the first.

With `jsonInput: true`, a build trusts the objects it checks to be plain data, as `JSON.parse` returns, so a Type rejecting undeclared keys counts a plain object's keys rather than checking each. On moltar's benchmark, it takes 0.82x a default build's cycles on parseStrict and 0.71x on assertStrict, level with ata's ahead-of-time build on parseStrict and 0.88x its cycles on assertStrict. Data with a declared key held non-enumerable can then pass with an undeclared key, as the options page shows.

A validator bakes `expression`, `description`, `json`, `toJSON`, `toJsonSchema` and `~standard.jsonSchema` only where the build follows it to code reading them, its dependencies' included, so the MCP SDK, the AI SDK, Elysia's OpenAPI plugin, hono-openapi and oRPC's converter get a JSON Schema with no `members` set, and one only validated bakes none. A build reading one module at a time, like webpack or Turbopack, bakes what each module reads of a validator it imports where it reads it. Reading one a validator lacks throws, naming the member and the setting, or reads `undefined` where a production bundle left out the validator's methods, which no bundle does where a `define` names a binding or, on webpack and Rspack, a loader after arktype's adds a read of one.
